# 第一章 数据清洗：从原始 SCADA 到可评分的数据集

**本章代码落点**：`src/wpf_benchmark/preprocessing/sdwpf.py`（342 行，单一文件即完整管道）
**运行命令**：`python -m wpf_benchmark preprocess`（服务器上压缩包已含清洗产物，此步可跳过，但原理必须掌握——它是评估口径的地基）

---

## 1.1 为什么清洗决定论文的可信度

风电功率预测论文的第一道审稿质疑通常不在模型，而在数据："你怎么处理缺失和坏点？限电样本算不算数？"处理方式不同，误差指标可以差出几十个百分点，模型排序甚至可能翻转。所以清洗设计要满足三条原则，本管道的每个环节都能对应回其中一条：

1. **物理先行**：凡是有明确物理依据的（温度量程、风功率曲线、角度周期性），用物理规则判别，而不是统计离群点方法硬套——物理规则可解释、可辩护。
2. **标记而非删除**：清洗管道不删除任何一行，只打布尔标记（flag/mask）；哪些标记的数据参与评分，由评估协议统一决定。这样"清洗"和"评分口径"解耦，换口径不用重跑清洗。
3. **防止信息泄漏**：归一化 min/max、清洗 P2 曲线与残差阈值、评估器参照曲线和 k 标定均只用前 196 天训练段；缺失填补仅用过去同机观测或当前时刻邻机观测。处理目标时刻的标记仍按该时刻实测值事后判定评分资格。

## 1.2 原始数据长什么样

| 项目 | 内容 |
|---|---|
| 主文件 | `sdwpf_245days_v1.csv`：245 天 × 134 台机组 × 每天 144 个 10 分钟步 |
| 特征（10 个） | `Wspd` 风速、`Wdir` 风向、`Etmp` 环境温度、`Itmp` 机舱温度、`Ndir` 机舱偏航角、`Pab1/2/3` 三支桨叶桨距角、`Prtv` 变流器无功、`Patv` **有功功率（预测目标）** |
| 辅助文件 | 机组坐标表 `x, y`（计算机间距离，空间填补和尾流图都要用） |

代码第一步把长表**透视成宽表**：每个特征变成 `(T=35280 时间点, N=134 机组)` 的矩阵（`sdwpf.py` 的 `load()`）。宽表形式让"对同一时刻所有机组"和"对同一机组所有时刻"两类操作（空间填补、逐机功率曲线）都变成矩阵切片，这是后文所有算法的数据结构基础。

**讨论要点**：10 分钟分辨率是风电功率预测的标准研究设定（与 SDWPF 数据集论文、KDD Cup 2022 官方任务一致）；预测视野 12 步 = 2 小时，属于超短期预测范畴。

## 1.3 管道总览与顺序设计

```
原始宽表
  │
  ├─ P1 物理范围硬规则 ──── 温度量程 / 风速界外 / 风向回绕 / 负功率截 0
  │
  ├─ 缺失三级递补 ───────── 连续缺失前 3 步因果前值 → 第 4 步起空间 kNN，记 m_imputed
  │
  ├─ P3a 停机判据 f_fault ── （先算出，供 P2 拟合功率曲线时排除停机行）
  │
  ├─ P2 功率曲线残差 ────── 离群点置缺失并重补（m_outlier）；限电标记 f_curtail
  │
  ├─ P3b 卡死/全场停机 ──── f_stuck（只查 Wspd）；f_farm（全场停机日）
  │
  └─ 输出：长表 Parquet（数据 + 全套标记列）+ meta（训练段 min/max）
```

**顺序为什么是这样**（讨论时容易被问）：

- **P1 在填补之前**：先把"确定是传感器错误"的值置为缺失（如温度 −50 ℃），插值才不会拿错误值当锚点。
- **f_fault 在 P2 之前**：停机行的功率（≈0）会严重拉低高风速箱的功率曲线中位数，所以拟合曲线前必须先识别停机并排除。
- **P2 的离群处置复用缺失流程**：离群的 `Patv` 不是随手删除，而是置为 NaN 后走同一套三级递补——填补值天然带 `m_imputed` 标记，评分口径自动一致。

## 1.4 P1：物理范围硬规则

**原理**：SCADA 传感器有物理量程，量程外的值按预设规则处理。本管道三条规则见 `sdwpf.py` 的 P1 段：

| 规则 | 处理 | 物理依据 |
|---|---|---|
| `Etmp/Itmp` ∉ [−40, 60] ℃ | 置 NaN，走缺失流程 | 工业温度计量程；场址为陆地风电场，极端气温不可能越界 |
| `Wspd` ∉ [0, 40] m/s | 置 NaN | 超过 40 m/s 已超绝大多数飓风，测风仪故障特征 |
| `Patv` < 0 | **截 0，不置缺失** | 负功率有真实物理含义：机组自耗电（偏航、变桨、加热系统），并非传感器坏；截 0 保留"机组在线但无出力"的信息 |

**风向回绕（角度回归的典型坑）**：风向是圆周量，−170° 和 190° 是同一个方向。直接把角度当普通回归量会让模型在 ±180° 处学到灾难性跳变。处理分两层：

1. 数据层（P1）：`(Wdir + 180) % 360 − 180` 把所有角度折回 [−180°, 180°)；
2. 特征层（输出前）：生成 `Wsin = sin(Wdir)`、`Wcos = cos(Wdir)` 两个连续特征（见 `sdwpf.py` 输出阶段）——模型用 Wsin/Wcos 可避开角度边界的数值跳变。

**讨论要点**：为什么 Patv<0 截 0 而不是当缺失？——本管道把负 `Patv` 截为 0，用非负值作为预测目标；这样会丢失自耗电大小，须如实说明。清洗没有把正功率统一截到额定值，评估器也不统一裁剪预测；不能说所有目标或预测都落在 [0, 1550] kW 内。

## 1.5 缺失三级递补：因果时间信息与空间信息

**原理**：在线预测只能使用发布时刻已观测到的信息。SCADA 缺失可能是零星丢点，也可能连续数小时；缺口刚出现时无法知道它最终会持续多久，因此按当前已连续缺失的步数切换填补来源：

- **当前连续缺失的前 3 步**：沿用同机过去最后一个有效值，不读取缺口之后的端点；
- **第 4 步起**：改用同一时刻空间近邻填补。即使一个缺口最终超过 3 步，其前 3 步仍按当时可见信息作因果填补。

三级递补主流程为 `sdwpf.py` 中的 `impute()`：

```
L0 结构空行：保留在时间网格中，按缺失处理（不虚构时刻）
L1 当前连续缺失前 3 步：逐列因果前值填补（fill_short）
L2 第 4 步起：同一时刻空间 kNN，k=12（knn_fill）
```

> **实测取舍**：训练段随机单点缺失实验中，因果前值的风速 MAE 为 0.607 m/s，空间 kNN(k=12) 为 0.459 m/s；双端线性插值为 0.450 m/s，但它需要未来端点，不能用于在线输入。这里保留前 3 步因果前值作为简单默认值，不声称它误差最小；其对最终预测性能的影响仍可做消融。

**L2 的两个设计细节**（讨论重点）：

1. **k=12 来自训练段标定**。`calibrate-k` 仅使用前 196 天，在随机单点与连续 4 小时缺口两种风速场景扫描 k；两者 MAE 均在 k=12 最低（0.459 与 0.415 m/s），详见开发版 `reports/k_selection.md`。服务器包不带报告，可在服务器重跑同一命令。
2. **距离倒数平方加权（IDW）**：`w = 1/d²`，近邻权重大、远邻权重小；只对邻居同一时刻的有限值加权。k=12 是候选邻居数，实际参与者可能因同时缺失而更少。

**防循环论证（本节最重要的一点）**：所有填补位置都记入 `m_imputed` 标记。如果填补后的数据进入评分，模型只要学会"复读插值"就能刷低误差——插值本身是平滑的，复读它几乎没有误差。这不是理论担忧：持续性好几条基线（`trend_persistence` 等）就有这种倾向。所以**主表评分排除所有 `m_imputed` 行**（见 1.7），填补只服务于"训练时特征不断供"，不参与评分。

**讨论要点**：为什么不用更先进的填补（矩阵分解、生成模型）？——本版优先用简单、因果的填补保证历史输入连续，并用标记区分观测与填补值。主表排除带插补标记的目标行，附表仍可能计入；填补质量也可能经历史输入影响预测，因此不能说填补器对最终指标零贡献。复杂填补器若要引入，应单独验证收益与泄漏风险。

## 1.6 P2：功率曲线残差——把物理规律当"异常检测器"

**原理**：风电机组的稳态功率近似由功率曲线唯一决定：$P = f(v)$，先慢启动、近额定风速处陡升、到额定（本场 1550 kW）后封顶。它是风况与出力之间最强的物理约束，天然是单点异常检测的参照系。

具体做法见 `sdwpf.py` 的功率曲线拟合与残差标记函数：

1. **逐机拟合参考曲线**：风速按 0.5 m/s 分箱，取每箱功率的**中位数**（不是均值——中位数对离群稳健，这正是我们在造"正常基准"）。样本不足的箱用有效箱线性插值补平，避免曲线端部毛刺；
2. **算残差**：$r = P_{观测} - \hat{f}(v_{观测})$；
3. **稳健阈值**：残差按"逐机 × 分风速箱"计算 $\sigma = 1.4826 \times \mathrm{MAD}$，$|z| = |r/\sigma| > 3$ 判离群。

**为什么用 MAD 而不是标准差**（统计学讨论点）：残差分布重尾（离群点本身就混在里面），标准差会被离群点自己撑大——用被污染的尺度去抓离群点，阈值越推越宽，抓不住。MAD（中位绝对偏差）的崩溃点 50%，几乎不受离群影响；系数 1.4826 使 MAD 在正态假设下与标准差一致（$\sigma = \mathrm{MAD}/\Phi^{-1}(3/4)$，$\Phi^{-1}(0.75)\approx 0.6745$，$1/0.6745\approx1.4826$）。所以 "$3\times1.4826\times$MAD" 就是"稳健版 3σ 准则"，辩护口径与经典 3σ 完全平行。

**两个防误杀细节**：

- 箱内样本 <100 时回退整机 σ，避免小样本箱的 σ 偶然过小；
- σ 下限 5 kW（见 `residual_flags()`）：低风速箱的功率本就近 0，MAD 可能很小；下限可防止阈值过紧。这是协议稳健性参数，不能直接解释为已测得的仪器分辨率。

**限电（curtailment）的判别——领域知识进入数据管道的地方**：残差**大幅负偏**（$z \le -3$）且风速 ≥5 m/s 的行标记 `f_curtail`。物理解释：机组能力正常但被调度指令压低出力，观测功率系统性低于风况应有的功率。限电行是"真实的功率响应"，但不是"自由风况下的功率响应"——预测模型若把它当正常样本学习，会在自由风况下系统性低估。处理方式是打标记交给评估协议（主表剔除），数值本身不动。

**离群点的闭环**：判为 `m_outlier` 的 `Patv` 置 NaN、走同一套三级递补重补——重补出来的值带 `m_imputed`，与天然缺失行同等待遇。

## 1.7 P3：工况异常标记

| 标记 | 判据 | 原理 |
|---|---|---|
| `f_fault` 停机 | `Patv ≤ 0` 且 `Wspd ≥ 3` | 有风无出力：故障、检修或待机，此时功率-风速关系被人为切断，不能当正常样本 |
| `f_curtail` 限电 | 残差 $z\le-3$ 且风速 ≥5 | 见 1.6，调度压出力 |
| `f_stuck` 卡死 | **仅查 Wspd**，连续 ≥6 步（1 小时）同值 | 风速计冻结（结冰、故障）是经典 SCADA 故障；**Ndir 长时间恒定是正常对风行为**、温度分辨率粗导致同值常见——后两者不作卡死判定，否则会误杀大量正常数据 |
| `f_farm` 全场停机日 | 当日所有“机组×时刻”格中，`f_fault` 为真的格数占比 >50% | 大范围无出力的日级标记；仅凭规则不能确定原因为调度或检修。该日目标被训练目标掩码与主表评分排除 |

`f_stuck` 只打标记不改数值（风速值还在，可能是真读数），风速监督目标使用它排除可疑段（方法模型 `pin.py` 的设计）。

## 1.8 标记体系与评估口径的对接（本章的落脚点）

清洗输出 **12 个数据列（10 个特征 + 2 个角度派生列）+ 11 个布尔标记列**。标记分两类：

**m 系（数据质量）**：`m_missing`（原始缺失）、`m_imputed`（任何来源的填补，含离群重补）、`m_outlier`（残差离群）
**f 系（工况状态）**：`f_fault`、`f_curtail`、`f_stuck`、`f_farm`

评估协议（`evaluation/config.py` 的 `exclude_flags_main`）定义主表评分排除：

```python
exclude_flags_main = ("m_missing", "m_imputed", "m_outlier", "f_fault", "f_curtail", "f_farm")
```

即：**主表**只纳入未触发这六项标记且 `Patv` 有限的目标格。附表（`all`）只要求清洗后的 `Patv` 有限，因而包含部分插补、停机和限电目标；它是宽松口径参考，不能等同于真实部署误差。这六个 flag 分别控制插补、离群与非自由风况对主表的影响。

两个通道级补充标记 `m_missing_wspd` / `m_imputed_wspd`（见 `sdwpf.py` 输出阶段）是后加的：方法模型的风速监督目标需要**逐通道**地知道哪些风速不可信（行级 `m_missing` 是 10 个通道任一缺失就标记，太粗），用它排除卡死段（`f_stuck`）之外的风速缺失/插补行，避免让模型去拟合插值风速。

**最终的量级感**（本版自检）：主表评分样本 4,948,656 格，附表 5,537,952 格；主表占附表 89.36%。评分单位是（发布时刻 × 机组 × 时距），同一目标时刻可被多个发布时刻预测，不能把这一格数与原始表 4,727,520 行直接比较。约 10.64% 的附表评分格被主表闸门排除；这描述覆盖率，不单独证明清洗规则最优。

## 1.9 清洗产物：26 列数据表的完整结构

清洗的最终输出是一张 **26 列 × 4,727,520 行**的 Parquet 表（= 35,280 个时刻 × 134 台机组，一行 = 某台机组在某 10 分钟的完整记录）。以下结构直接从产物文件读出，分三组：

**第 1 组：身份与时间（3 列）**——每一行的"坐标"：

| 列 | 含义 |
|---|---|
| `ts` | 时间戳（时间网格主键） |
| `Day` | 第几天（1–245），评估协议按它切 196/25/24 三段 |
| `TurbID` | 机组编号（1–134） |

**第 2 组：数据列（12 列）**——模型吃的东西：

| 列 | 含义 | 说明 |
|---|---|---|
| `Wspd` | 风速 | 核心输入 |
| `Wdir` | 风向（已回绕到 [−180°, 180°)） | 留给需要真实角度的模块（如尾流标定） |
| `Wsin` / `Wcos` | 风向的 sin/cos 编码 | 模型实际用的角度特征，无跳变 |
| `Etmp` / `Itmp` | 环境温度 / 机舱温度 | 辅助特征 |
| `Ndir` | 机舱偏航角 | 对风状态 |
| `Pab1/2/3` | 三支桨叶的桨距角 | 限电/调速时叶片角度会变，是工况的间接信号 |
| `Prtv` | 变流器无功功率 | 辅助特征 |
| `Patv` | **有功功率（预测目标）** | 负值已截 0 |

**第 3 组：标记列（11 列，全布尔）**——"这行/这个格子可不可信"的说明：

行级标记（整行一个布尔值）：

| 列 | 贴纸含义 | 谁用它 |
|---|---|---|
| `m_missing` | 10 个**原始特征列**中任何一列有原始缺失（Wsin/Wcos 为派生列，不单独计入） | 评分排除 |
| `m_imputed` | 该行**任何一列**被填补过（含离群重补） | 评分排除（防循环论证的关键列） |
| `m_outlier` | 该行功率被判残差离群 | 评分排除 |
| `f_fault` | 有风（≥3 m/s）无出力，疑似停机 | 评分排除 |
| `f_curtail` | 疑似限电（残差大负偏 + 风速 ≥5 m/s） | 评分排除 |
| `f_stuck` | 风速计连续 ≥6 步同值，疑似卡死 | 风速监督目标排除；评分暂不排 |
| `f_farm` | 当日停机的机组×时刻格占比超过 50% | 主表评分排除 |

通道级标记（后加的，只看单一通道）：

| 列 | 贴纸含义 | 谁用它 |
|---|---|---|
| `m_missing_wspd` / `m_imputed_wspd` | **风速这一列**原始缺失 / 被填补 | 方法模型的风速监督目标用它排除——不拿编造的风速教模型 |
| `m_missing_patv` / `m_imputed_patv` | **功率这一列**原始缺失 / 被填补 | 功率通道的精细控制，备用 |

**为什么要"行级 + 通道级"两套标记**：行级 `m_missing` 是最粗粒度——10 个原始特征列里任何一列缺，整行就贴（派生的 Wsin/Wcos 不参与判定）。但方法模型有个特殊需求：风速也当监督目标，它需要知道"风速这一列本身可不可信"，而不是"这一整行干不干净"。一台机组风速完美、只是温度缺了，行级标记说它是"脏行"，通道级标记说"风速没事"。两套并存：评估协议用行级的（保持口径稳定），风速监督用通道级的（精细控制），互不干扰。

**下游使用方式**（一张表收拢全章）：12 个数据列 + `TurbID`/`ts` 用来拼滑窗，`Day` 用来切训练/验证/测试，11 个标记列用来决定"谁有资格进评分、谁有资格当监督目标"。数据本身和"数据可信度说明"打包在同一张表里，这是"标记而非删除"原则的最终落地形态。

## 1.11 与导师讨论的问题预案

**Q1：插补行既然不评分，为什么还要插补？**
训练时滑窗特征需要连续（模型输入是 144 步历史）；插补能减少输入断供。`m_imputed` 使这些目标行不进入**主表**评分，风速通道标记用于控制风速监督；附表仍可能包含插补目标。填补值可以进入历史输入，因此其质量仍可能影响预测。

**Q2：k=12、短缺口 3 步、卡死 6 步、残差 3σ——这些超参数怎么辩护？**
分两类：k=12 由 `calibrate-k` 只在训练段标定（两种遮掩场景都选到 12；见 `reports/k_selection.md`）。其余（3 步/6 步/3σ）是领域常规与防误杀约束（σ 下限 5 kW、箱内 ≥100 样本、卡死只查 Wspd）构成的默认值；`reports/cleaning_report.md` 记录了 flag 的影响量级。这些默认值还需敏感性分析，不能称为已标定最优。

**Q3：限电样本为什么不做"限电功率还原"，直接剔除？**
还原需要知道调度指令（数据里没有），任何还原都是猜；剔除（仅从主表评分剔除，数值保留）是唯一不引入假设的处理。可作为 limitation 主动写进论文。

**Q4：这套清洗会不会把"难预测的样本"都删了，让指标虚低？**
主表按预设的数据质量与工况规则排除目标行，不按模型误差挑样本；但难例若同时触发缺失、停机、限电或离群标记，也会被排除，不能说“大风突变、爬坡等难例完整保留”。应报告分风速段和爬坡阳性格的保留率，并对照附表，检验选择性覆盖的影响。

**Q5：和 KDD Cup 2022 官方/其他论文的处理相比呢？**
官方基线对缺失的处理粗得多（多数直接均值/前值填补且不排除评分），本管道在"评分排插补 + 限电剔除 + 稳健残差"三点上更严格，主表指标因此略保守——这是可比性讨论时的诚实论点：我们的数字更"硬"。

## 2.1 为什么协议要先于模型存在

科研评估最大的陷阱是"事后挑指标"：模型跑完了，哪个指标好看就重点报哪个，换一套划分再试一次——审稿人一眼识破，且这种偏差（选择偏差）无法事后补救。防范办法是**预注册**：在跑任何模型之前，把"用哪段数据考试、预测多远、谁有资格计分、怎么算分"全部写死成配置，之后所有模型（包括你自己的方法）无一例外走同一套流程。

本项目的协议预注册在 `docs/spec_eval_protocol.md`，落成 `evaluation/config.py` 中 `ProtocolConfig` 的带默认值参数。这带来三个可核对的好处：

1. **公平可比**：15 个模型共用一个评估器和数据协议；解读差异时仍需核对模型结构与训练损失；
2. **防泄漏有据**：训练/验证/测试的边界、防泄漏条款都写在协议里，跑之前就定死；
3. **可扩展不动地基**：新模型注册后自动获得全部指标（"任何模型接入后不改指标代码"是协议的验收标准之一）。

## 2.2 任务设定：预测什么、切在哪里

**任务**：给定每台机组过去 `input_window = 144` 步（1 天，10 分钟分辨率）的特征历史，预测未来 `horizon = 12` 步（2 小时）的 `Patv`。134 台机组同时预测——这是**多机时空预测**任务，单机模型只用了数据潜力的一个维度。

**数据划分**（按时间，严禁 shuffle）：

| 段 | 天数 | 用途 |
|---|---|---|
| 训练 | Day 1–196 | 拟合模型参数、统计量、功率曲线 |
| 验证 | Day 197–221（25 天） | 选超参数（λ、epoch）、早停 |
| 测试 | Day 222–245（24 天） | **每个冻结配置只跑一次** |

**为什么严禁 shuffle、必须按时间切**——这是时序任务的第一戒律，值得完整讲给导师听：

- 若随机打乱后抽样划分，测试集的"昨天"可能出现在训练集里：模型背下了相邻时刻的功率，测试误差虚低。10 分钟分辨率下相邻点相关性极强，这种泄漏可以让误差看起来好数倍；
- 更根本的理由：**真实部署中你永远只有过去**。按时间切分模拟了真实使用场景——用历史 196 天训练，预测"未来"。shuffle 划分回答的是一个不存在的问题；
- 验证段夹在中间也是同理：早停和选 λ 看"未来 25 天"的表现，模拟"模型上线后最近的表现"。

196/25/24 ≈ 8:1:1，与 SDWPF 数据集论文及 KDD Cup 2022 官方任务的时间划分惯例一致，保证与文献可比。

## 2.3 预测数组的统一约定

所有模型的输出被统一成同一个三维数组（`runner.py`）：

$$\hat{P} \in \mathbb{R}^{T_{\text{eff}} \times N \times H}, \quad T_{\text{eff}} = T_{\text{test}} - H$$

- `T_eff` 个"发布时刻"：每个发布时刻用此前 144 步历史，发出一份 12 步预测；
- `N = 134` 台机组、`H = 12` 个时距；样本 t 的第 h 列预测目标时刻 t+h；
- 真值数组用**完全相同的堆叠方式**从测试段切片得到，预测与真值逐元素对齐。

这个约定让"评估"变成纯数组运算：任何模型只要按接口吐出这个形状，全部指标自动可用。规格书 §8.1 专门记录了堆叠切片的差一错误（`base[h : T−H+h]`）——这类 off-by-one 是评估代码最阴险的 bug，错了指标照常出数，只是全员系统性偏移，不显错。**自检（2.6）存在的意义就是抓这类错误**。

## 2.5 五层指标体系

协议把指标组织成 A–E 五层（`evaluator.py` 中逐一实现）。分层的逻辑是**从"准不准"到"有没有用"再到"合不合物理"**，每层回答一个不同的问题。

### A 层 · 精度主表——"整体差多少"

四个指标：MAE/RMSE/NMAE 提供单机级与场站级双口径；**SS 仅单机级**（它定义为对 persistence 的相对改进，persistence 参照只在单机口径上计算）：

| 指标 | 定义 | 特点 |
|---|---|---|
| MAE | mean(\|e\|)，e = P̂ − P | 主指标：对离群稳健，量纲直观（平均差多少 kW），风电预测文献标准口径 |
| RMSE | sqrt(mean(e²)) | 大误差权重高：暴露"灾难性失误"，与 MAE 的差值反映误差分布的尾部 |
| NMAE | 单机：MAE / 1550 kW × 100%；场站：逐格绝对场站误差除以该格有效机组数 × 1550 kW，再平均 | 无量纲化；场站口径随有效机组数改变分母，比较时须说明有效率闸门 |
| 技巧分 SS | 100 × (1 − MAE_模型 / MAE_持续性) | 相对改进量：负值 = 还不如最笨的基线 |

**单机级 vs 场站级**（易被问到的口径细节）：

- 单机级：把所有 (时刻, 机组, 时距) 的有效样本池在一起算——反映"一台机组平均预测水平"；
- 场站级：对每个合格的（发布时刻 × 时距）格，把**有效机组**误差求和，再对这些格算 MAE/RMSE。不同格的有效机组数可变，故这是部分场站误差；机组间的高估与低估可以抵消。NMAE 每格按对应有效机组的额定容量归一化，再取平均。

场站级有一个实现层面的陷阱：主表闸门会排除部分机组，若要求"134 台全有效才能计入"，本版测试段场站级将是**空集**。协议保留 `farm_min_valid_frac = 0.85`：至少 85% 机组有效才计入。下表是固定该阈值后对本版测试段 3456 个时刻的覆盖率诊断，不能反过来用测试段挑阈值：

| 每时刻有效率的实测分布 | 阈值扫描（能进入场站级评分的时刻占比） |
|---|---|
| 最大 **0.948**（本版观测最大值，不是物理上限）<br>中位数 **0.933**<br>最小 0.000（全场停机时刻） | ≥1.00 或 ≥0.95 → **0%**<br>≥0.90 → **68.87%**<br>**≥0.85 → 81.57%**<br>≥0.80 → **89.76%** |

本版 `0.85` 阈值下，有 81.57% 的发布时刻通过有效率条件；场站指标实际按（发布时刻 × 时距）格统计，共 33,709 个合格格。阈值保留在 `ProtocolConfig` 中，后续可在验证段做敏感性分析。

**本版场站口径**：主表 persistence 自检的场站 MAE 为 5029.75 kW、NMAE 为 **2.67%**。NMAE 使用每格有效机组容量作分母，避免缺机组时把部分场站误差除以固定满场容量而低估比例。

**SS 的参照为什么选 persistence**：持续性（P̂(t+h)=P(t)，把最后观测值当预测）是最诚实的下界——它不含任何可学参数，任何"技巧"都必须来自模型真的学到了东西。同时它是风电预测文献的惯例参照，SS 直接回答审稿人"你的模型比死拿住最后一个观测值强多少"。

### B 层 · 误差结构——"误差藏在哪里"

A 层的均值会掩盖结构，B 层把误差拆开看：

1. **逐时距误差曲线**（h=1..12 各自的 MAE/RMSE）：预测 10 分钟后 vs 2 小时后差多少。这条曲线是超短期预测的"身份证"——好模型应该衰减得**慢**（学到了趋势和时空结构，误差不随视野快速膨胀）；这条曲线直接生成论文图 6。
2. **分风速段误差**（按目标时刻**实测**风速分 6 箱：0–3/3–6/…/15–40 m/s）：预期规律是额定风速附近（9–12 m/s，功率最陡峭段）和高风速段最难——前者功率对风速的导数最大，风速小误差被放大成大功率误差。→ 论文图 7。
3. **偏差分解**：ME（平均误差，正=系统性高估）、高估占比、低估占比。对电网而言高估和低估的代价不对称（备用容量 vs 切负荷），Chen 等 (2022) 专门论证了这种不对称的经济后果——这一条是连接"预测精度"与"经济价值"叙事的接口。
4. **分块稳定性**：测试段按 7 天一块分别报 MAE——检查模型是否在某些天气 regime 下失效，防止"平均分好看、个别周崩盘"。

### C 层 · 工业事件——"关键时刻扛不扛得住"

电网最怕的不是平时差 50 kW，而是关键时刻掉链子：

1. **爬坡逐格判别**：对每个（发布时刻 × 机组 × 时距）格，真实阳性定义为 |P(t+h) − P(t)| ≥ 155 kW（额定 10%）；比较模型是否在同一格报阳性，计算逐格 recall / precision / F1 和真实阳性格上的功率 MAE。持续性恒预测 P(t)，所以预测阳性格为 0、recall=0，precision 因分母为 0 记为 NaN。

**口径说明**：本版保留逐格口径，自检真实阳性 **660,412 格**。同一爬坡过程可能对应多个发布时刻或时距，格之间也不独立；不能把这个数称为 660,412 次事件，也不能据此直接断言统计显著性。若论文需要工业事件级召回率，须另行定义事件边界、匹配容差和事件级评分。
2. **合格机组子集的逐日电量误差**：只用 `h=1` 预测，对每个有资格评分的目标时刻与机组，把 10 分钟功率折算为 MWh 后按测试日求和，再计算 MAE/MAPE。首日只覆盖 143/144 步，末日 133/144 步；未覆盖或被闸门排除的机组不计入。它反映该子集的日尺度偏差，**不是完整风场日电量或结算电量**。
3. **大风段**（实测风速 ≥18 m/s）：大风是稀缺而高危的工况（接近切出、功率封顶段），单独报，样本不足时如实注明。

### D 层 · 物理合理性——"预测像不像真的功率"

这是**物理信息方法（你的创新主线）与评估协议的接口**，三个指标：

1. **功率曲线违背率**：预测功率与"该风速下训练段拟合的功率曲线"偏离超过 3σ 的比例。三个关键设计：
   - 参照曲线**只在训练段拟合**；评估器和清洗管道分别拟合各自所需的曲线与尺度，均不使用验证/测试段做参数估计；
   - 查曲线用目标时刻的**实测**风速，模型预测的风速不参与——评估的是"给定真实风况，预测功率在物理上合不合理"，而不是"预测的风-功组合合不合理"，后者会把风速预测的误差混进来；
   - **同时报告真实值的违背率作参照**：本版主表实测为 **0.73%**，是参照值而非理论下限。persistence 的违背率为 **17.70%**。方法模型若降低该指标，还需同时检查 MAE，避免仅靠把预测压到参照曲线上取得低违背率。
2. **负功率率**：mean(P̂ < 0)——相对于本协议的非负目标口径，统计预测越过下界的比例；原始负功率可能反映自耗电，不能笼统称为物理不可能。
3. **超额定率**：mean(P̂ > 1550)——统计预测超过额定铭牌功率的比例；本版清洗后仍有少量观测值超过 1550 kW，该指标是模型输出边界诊断。

### E 层 · 概率化（占位）

`"E_probabilistic": null` 留位：pinball loss、PICP/PINAW（区间覆盖率与宽度）、CRPS。点预测做到位后，区间预测是自然的第二篇/扩展方向，接口已预留。

## 2.8 与导师讨论的问题预案

**Q1：为什么主指标选 MAE 而不是 RMSE？**
三个理由：① 风电功率预测文献与 KDD Cup 官方评测以 MAE 为主口径，可比性优先；② MAE 对离群稳健，而我们的数据虽经清洗仍存重尾；③ MAE 直观（"平均差多少千瓦"），与 NMAE、SS 构成完整链条。RMSE 并列报告，其与 MAE 的差值用于刻画误差尾部——两个都报，主次分明。

**Q2：196/25/24 天的划分依据？**
245 天的 8:1:1，与 SDWPF 数据集论文和 KDD Cup 2022 官方设置一致；比例写在 `ProtocolConfig` 里可调，但主实验不动它——动了就无法与文献和自己的历史实验可比。

**Q3：限电行剔除后，评估是不是回避了真实部署的难题？**
主表排除疑似限电行，因此不测这类工况下的完整部署表现。附表只要求清洗后功率有限，可用于查看包含疑似限电等工况的宽松口径误差，但也可能计入插补目标，不能等同部署真值。若要研究限电预测，应另行定义调度信息和评价目标。

**Q4：场站级 0.85 阈值会不会太松/太紧？**
0.85 是当前协议的固定阈值，本版测试段约 81.57% 的发布时刻满足有效率条件；这个覆盖率只描述结果，不能用测试段反向选阈值。下一步应在验证段扫描合理阈值，连同覆盖率、场站 MAE/NMAE 和被排除工况一起报告，再冻结主实验阈值。

**Q5：违背率的参照是 0.73%，我的方法做到多少算成功？**
0.73% 是本版主表真实功率自身的违背率，**是参照值而非理论下限**；合理目标是降低 persistence 的 17.70%，同时保持或改善 MAE。过度约束物理性可能牺牲精度，D 层与 A 层必须联合呈现。

**Q6：爬坡 recall/precision 会不会样本太少不稳定？**
协议报告真实阳性格数 `n_positive_cells`；本版主表自检为 **660,412 格**。这些格由重叠时距产生，不能按独立样本数量解释。persistence 的逐格 recall=0、precision=NaN 是结构性结果（它不报阳性格），验证了除零护栏；事件级表现尚未评估。

## 3.1 基线阶梯：每一级多"学"一点什么

15 个注册名不是随便凑的，它们构成一座**逐级递进的阶梯**，每一级比上一级多用一分学习能力：

| 层级 | 注册名 | "学"了什么 | 存在理由 |
|---|---|---|---|
| 参照 | `persistence` | 什么都不学，抄最后观测 | 误差下界 + 技巧分参照 |
| 规则 | `seasonal_persistence` | 用"日周期"这一条领域知识 | 检验日周期结构的价值 |
| 规则 | `climatology` | 训练段每机组×每时刻的平均功率 | 检验"气候均值"的价值 |
| 规则 | `trend_persistence` / `farm_mean_persistence` | 近 1 小时单机/全场趋势外推 | 检验短时趋势的价值 |
| 传统学习 | `linear` | 从数据学 145×12 的线性映射 | 检验线性可解释成分 |
| 传统学习 | `gbdt` | 学窗口统计量的非线性组合 | 检验手工特征的非线性上限 |
| 深度学习 | `lstm_seq2seq` | LSTM 编码、MLP 多步输出 | 项目内循环网络路线基线，非原论文逐层复现 |
| 深度学习 | `patchtst` | 分片 Transformer 编码 | 项目内受 PatchTST 启发的简化基线 |
| 深度学习 | `agcrn_lite` | 自适应图与池化后的循环时序 | 项目内受 AGCRN 启发的原简化基线 |
| 深度学习 | `agcrn` | 原论文 DAGG、NAPL、完整时序与直接多步输出 | 论文 AGCRN 架构在本项目数据协议下的实现 |
| 方法模型 | `ours` 及三变体 | 图网络 + 物理损失 | 本文创新（第四章） |

**阶梯的方法论价值**：这些基线覆盖规则、线性、循环、注意力与图结构路线，能显示本方法相对项目内不同能力基线的表现。`agcrn_lite` 与方法模型共享骨干；`agcrn` 使用原论文架构，但输入、数据集与训练预算仍按本项目协议。旧 Wave 1 报告里名为 `agcrn` 的运行来自现在的 `agcrn_lite`，不能作为新版 `agcrn` 的实测结果。物理损失的单项贡献需看共享骨干的消融。

## 3.2 BaseForecaster 契约：接口即公平

所有模型继承 `models/base.py` 的 `BaseForecaster`，契约只有四个类属性和三个方法：

```python
class BaseForecaster:
    features = ("Patv",)          # ① 声明需要清洗表的哪些列
    history_scale = "physical"    # ② 物理单位 或 "normalized"（训练段 min/max 缩放）
    needs_phases = False          # ③ 是否需要"日内时刻"辅助信息
    n_params = 0                  # ④ 参数量（记录进结果，报告计算开销用）

    def configure(self, config, scaler): ...   # runner 注入协议配置和缩放器
    def fit(self, train, valid=None): ...      # 只给训练段（和验证段）
    def predict(self, history) -> (N, H): ...  # 单发布时刻：134 台 × 12 步
    def predict_batch(self, histories, phases=None): ...  # 批量版，GPU 模型重写
```

**这个契约为什么能保证公平**——每一条都堵住一种作弊途径：

- `fit` 只拿训练/验证段 DataFrame，**接口上就拿不到测试段**：想偷看未来，得绕过接口改 runner，代码审查一目了然；
- `history_scale` 的缩放统计由 runner 统一注入（来自 `sdwpf_meta.json` 的**训练段** min/max），模型自己无权用全数据算归一化——归一化泄漏在接口层被禁止；
- `predict` 拿到的历史窗口是 runner 切好的，模型无法自行选择"从测试段哪个位置开始看"——时间对齐责任全部收归 runner，一个实现、处处一致；
- 深度模型重写 `predict_batch`（每次喂一批发布时刻），但**输出契约不变**：批次内每行仍是 (134, 12) kW。runner 不关心你内部是循环还是 GPU 并行。

**讨论要点**：`history_scale` 提供两种选项是刻意设计。规则基线用 `physical`（如 persistence 直接抄值，物理单位最自然）；深度模型用 `normalized`（神经网络对输入量纲敏感，min/max 归一化后训练稳定），但输出必须自己缩放回 kW（`neural.py` 的 predict 里 `pred*span + low` 并截断到 [0, 1550]）——**模型内部随便用什么单位，接口两侧永远流通物理单位的功率**。

## 3.3 注册表：三行代码接入一个模型

`models/registry.py` 是一个极简机制：

```python
MODEL_REGISTRY: Dict[str, Type[BaseForecaster]] = {}

def register_model(name: str):
    def decorator(cls):
        if name in MODEL_REGISTRY: raise ValueError(...)   # 防重名
        cls.name = name
        MODEL_REGISTRY[name] = cls
        return cls
    return decorator
```

接入一个新模型的全部步骤：① 写文件、类上挂 `@register_model("my_model")`；② 在 `models/__init__.py` 加一行 import；③ 写一个配置 JSON。之后 `run --model my_model` 自动获得：协议切分、训练段统计注入、三维数组组装、五层指标、JSON 结果（含 main/all 两表）与 NPZ 预测数组、index.jsonl 登记（run 不生成逐次 Markdown）——**评估代码零改动**（这是预注册协议的验收标准，2.1 节的承诺在此兑现）。

这个模式的价值不止省事：**注册表让"模型"成为可枚举的封闭集合**，任何结果 JSON 里的模型名都能反查到确定的类和 `model_config`——实验的可追溯性由此而来。

## 3.4 runner：把前两章焊在一起

`runner.py` 是模型与评估器之间的搬运工，一次 `run` 的完整流水线：

```
读协议配置 → seed_all(seed)（固定随机种子）
→ 按模型 features 读列、按 Day 切三段
→ model.fit(train, valid)          ← 模型唯一的学习机会
→ 测试段：借测试段之前的 prior 数据补齐头部历史（2.3 的"头部"问题）
→ 对 T_eff = 3456−12 = 3444 个发布时刻，按批调 predict_batch
→ 堆成三维预测数组 (3444, 134, 12)
→ evaluator.evaluate(preds, table="main"/"all")
→ 存 JSON + npz 预测数组（供论文图 5/8/11 用）+ 登记 index.jsonl
```

细节：需要"日内时刻"的模型（climatology）由 runner 附带 `phases` 数组；推理批大小由 `--batch-size`（默认 32）控制，与训练批无关。

## 3.5 基线逐个点评：每个的"信条"与结构

### 规则基线（不学习，纯查表/外推）

- **`persistence`**：信条"风况 2 小时内不变"。预测 = 历史窗最后一步的功率。它是全项目**唯一没有 fit 逻辑**的模型，也是 SS 的分母。
- **`seasonal_persistence`**：信条"明天此刻 = 今天此刻"。预测 = 历史窗中 24 小时前同位置的值（fit 检查窗口至少覆盖一整天：`input_window ≥ steps_per_day`）。
- **`climatology`**：`fit` 对训练段有效行按（机组 × 日内 144 时刻）建均值查表；当前 `predict_batch` 使用**发布时刻相位**查一次，并将该值重复到全部 12 个时距。表 3.7 的 344.00 kW 对应这一实现。是否改为逐目标时刻相位查表待决定；若改，须重跑基线。
- **`trend_persistence`**：信条"近 1 小时的变化趋势会延续"，作用于单机功率。
- **`farm_mean_persistence`**：实际机制是**全场均值比率缩放**——用近 1 小时全场平均功率的比值缩放每台机的最新功率，再把同一值重复到全部 12 个时距（非趋势外推）；检验"全场尺度信息能否校正单机偏差"。

### 传统学习基线

- **`linear`**（`linear.py`）：逐机组拟合岭回归，输入归一化功率的 144 步窗口（+截距），多输出 12 步。α=1.0 正则防过拟合；每 6 步取一个训练窗口控制规模；训练样本不足的机组回退为 persistence（抄最后观测），`fallback_turbines` 如实记录。**它的角色是"线性成分标尺"：深度模型赢它赢多少，就是非线性的价值。**
- **`gbdt`**（`gbdt.py`）：以窗口统计量（末值、均值、标准差、最小/最大、斜率等，无分位数）为特征训 LightGBM，装不上时自动回退 XGBoost。手工特征 + 梯度提升是"不搞深度学习能做到的上限"的代表。

### 深度基线（共用 `NeuralForecaster` 训练骨架）

四个模型共享同一套训练循环（`neural.py`）和数据划分。`agcrn` 默认按论文设置使用 MAE，其余三个默认使用 MSE；因此 `agcrn` 与其他模型的比较同时包含网络结构和训练损失差异，不作单因素归因。

- **`lstm_seq2seq`**：编码器 `nn.LSTM(4→128, 2层)` 逐步读完 144 步历史，MLP 头一次输出 12 步。这是项目内的 LSTM 编码基线，**没有原始 seq2seq 的循环解码器**。
- **`patchtst`**：把 144 步按"窗口 12、步距 6"切成 23 个 patch，线性投影 + 位置编码后过 2 层 Transformer 编码器；各特征通道在编码器中分开处理，预测头再拼接各通道编码。机组间不交互。这是借鉴 patch 与独立通道编码的项目实现，**不等于原论文完整 PatchTST**。
- **`agcrn_lite`**（`networks.py`）：原项目简化基线。邻接矩阵由可学习嵌入生成；`GraphCell` 聚合邻机状态；144 步按 `temporal_stride=6` 平均成 24 个时间片。它没有原 AGCRN 的节点自适应参数学习模块，是方法模型的共享骨干；与方法模型的比较见 4.8-Q3。
- **`agcrn`**（`agcrn_original.py`）：按原论文实现共享节点嵌入生成自适应图、切比雪夫图卷积、节点自适应参数、堆叠循环单元和直接多时距输出头。输入完整 144 步；默认 MAE 损失。数据、输入特征与训练轮数仍遵循本项目协议。

**深度基线的对照组设计**：LSTM 编码（无机组交互）→ 分片注意力（无机组交互）→ 简化图循环与论文架构图循环（机组交互）。若图循环基线最好，可作为机组交互有用的项目内证据；不能据此声称原论文模型的跨数据集排名。

## 3.6 深度训练协议：三条纪律

深度模型的训练设置不是随手写的默认值，每条都有方法论理由：

1. **硬上限**：构造函数强制 `epochs ≤ 30`、`batch ≤ 512`（`neural.py:29`）——防止"把训练轮数调到 200 刷验证集"，超参数搜索空间被协议钳住，所有深度模型在同等预算下比较；
2. **早停 + 最优轮回滚**：验证段训练损失连续 5 轮无进步即停，**用验证损失最小的那一轮的权重**做测试预测；`agcrn` 默认监控 MAE，其余模型监控 MSE；
3. **3 种子重复**：`--repeat 3` 顺序用 seed 0/1/2，训练初始化和数据顺序的随机性被显式平均，主表报**均值 ± 标准差**。深度学习结果的标准差往往和模型间差异同量级，单种子对比是审稿必杀的硬伤。`seed_all` 在每次运行前固定 numpy/torch 全部随机源，结果可复现。

训练窗口每 `stride=6` 步取一个（训练段 28224 步 ÷ 6 ≈ 4700 个发布时刻；单机模型再乘 134 台机组展开成约 63 万个训练样本）。`agcrn` 默认优化归一化功率的 MAE，其余深度模型默认优化 MSE；目标格子的资格掩码同步进损失，被闸门排除的格子不产生梯度。

## 3.7 实测结果解读：为什么基线普遍打不过 persistence

开发版在完整数据上的实测主表 MAE（单机级）：

|---|---|---|

**这不是 bug，是这份数据的重要物理事实**：10 分钟尺度的功率自相关远强于日周期和线性趋势——2 小时内风况通常连续变化，"抄当前值"就是最强的一阶近似。三个含义：

1. **论文如实报告**，且把"强短期持续性"写成数据集特性（KDD Cup 2022 官方分析同样指出这一点），不是遮掩；
2. **模型还需比较误差结构**：B 层逐时距曲线、C 层爬坡逐格命中率（persistence recall=0）、D 层违背率（persistence 17.70%，真实值参照 0.73%）。这些指标补充 A 层平均误差，但须用实际模型结果验证是否有优势；
3. **对方法模型的预期要现实**：主表 MAE 上的改进可能是几个百分点而非腰斩，卖点应放在 B/C/D 层的结构性优势上。

## 3.8 与导师讨论的问题预案

**Q1：深度基线只有三个，会不会太少？**
覆盖了循环 / 注意力 / 图网络三条主流路线，且结构对比构成受控实验；基线数量由"每条路线都跑 3 种子"的质量要求约束——5 个基线 × 3 种子的算力不如 3 个基线的完整证据链。引用文献时选同路线的最强代表即可。

**Q2：为什么 persistence 这么强还能当参照？它的 SS 公平吗？**
公平且必要：SS 的意义是统一换算"相对改进"，persistence 无参数、无训练、无超参，是唯一不可能被过拟合的参照。所有文献用同一参照，跨论文可比。

**Q3：深度模型共享训练骨架，会不会"串味"？**
共享的是训练纪律（早停、轮数上限、窗口采样、损失掩码），不同的是网络结构——这正是受控变量。若各自用各自的训练代码，"谁好"就分不清是结构好还是训练调得好。

**Q4：方法模型和 agcrn_lite 共用网络，消融怎么保证差异只来自物理损失？**
四变体（`ours` 及消融）与 `agcrn_lite` 用同一个 `AGCRNLiteNetwork` 类、同一训练循环、同一超参配置；变体之间只差损失权重 λ。论文架构的 `agcrn` 是独立基线，不用于这一共享骨干归因。

**Q5：单机模型（linear/seq2seq/patchtst）和图模型（agcrn_lite/agcrn）在 runner 里走同一条路吗？**
是。`graph_model` 标志只影响训练时批的组织方式（图模型按发布时刻成批、134 台整体进出；单机模型把 (时刻×机组) 展平成独立样本）和推理批次形状，评估端看到的三维数组完全相同——**交互结构是模型的内部自由，接口不变**。

# 第四章 方法模型与消融：物理信息如何进入图网络

**本章代码落点**：`src/wpf_benchmark/models/pin.py`（方法模型与四变体）、`power_curve.py`（可微功率曲线）、`wake.py`（尾流先验）、`analysis/wake_calibration.py`（W0 标定）
**实验流程**：`docs/method_ablation.md`（W0→W2→W3 预注册步骤）

---

## 4.1 方法总览：一个网络、两个输出、两个物理损失

方法模型（`PINForecaster`）的完整主张用一句话说：**在图网络骨干上，让网络同时预测未来功率和未来风速，并用两个物理规律把两者拴住**。拆开是三个部件：

```
                 ┌─ 输出头1：未来12步功率（主任务，评估就评它）
AGCRN-lite 骨干 ──┤
（与基线agcrn_lite同构）└─ 输出头2：未来12步风速（辅助监督，永不进入输入）

损失 = 功率MSE + 风速MSE
     + λ_consist × 一致性损失（预测功率-预测风速 过功率曲线）
     + λ_wake   × 尾流损失（学习图 ≈ 训练段标定的尾流先验图）
```

**为什么风速是输出而不是输入**——这是方法的第一性设计，值得完整讲：历史风速当然在输入里（144 步特征窗含 Wspd），但**未来**的真实风速只有观测数据里有、部署时不存在。若把未来风速当输入，就是用未来预测未来（泄漏）；若只用它算辅助损失（多任务学习），它扮演的是"物理教师的参考答案"——告诉网络"你隐含推断的风况应该能经功率曲线解释你输出的功率"。部署时输入只有历史，两个输出头照常工作，一致性约束依然成立。

**双输出互相构成对方的"物理检验器"**：功率头若输出的值与风速头隐含的风况在功率曲线上对不上，一致性损失就惩罚它。这把 D 层评估指标（违背率）从"事后检查"前移成了"训练目标"，方法与评估在物理上呼应。**注意两者并非同一个量**：D 层评估用目标时刻的**实测**风速查曲线，一致性损失用模型的**预测**风速——相关但不同，论文中不能混同表述（4.8-Q1）。

---

## 4.2 共享骨干：与 agcrn_lite 基线只差一个输出头

`pin.py` 的 `_build_network` 返回 `AGCRNLiteNetwork(..., output_wind=True)`——与本项目的 `agcrn_lite` 基线共用网络类与训练框架，主要设计差异为：

- 基线 `agcrn_lite`：输出头只产出 12 步功率，损失只有功率 MSE；
- 方法模型：输出头产出 24 维（12 功率 + 12 风速），损失多三项。

**这是消融实验干净性的基石**：四变体之间唯一的自变量是 λ 权重（结构、数据、训练纪律全同）；方法模型与 `agcrn_lite` 基线之间则是"风速辅助头 + 损失项"的**设计包差异**（骨干网络同类、输出维度与损失项不同）——后者的总效应归因需按 4.8-Q3 的两级对照链拆分。论文架构的 `agcrn` 与方法模型骨干不同，不能放入这条单因素归因链。

---

## 4.3 两个物理损失逐个拆

### 一致性损失（`pin.py` 的 `_loss_terms`）

$$L_{\text{consist}} = \frac{1}{|\mathcal{B}|}\sum_{(b,i,h)\in\mathcal{B}} \big| \tilde{P}_{b,i,h} - f_{\text{curve}}(\tilde{v}_{b,i,h}) \big| \;/\; P_{\text{rated}}$$

- $\tilde{P}, \tilde{v}$ 是网络在**归一化空间**的两个输出，先反缩放回物理单位（功率 kW、风速截到 [0, 30] m/s）；
- $f_{\text{curve}}$ 是 `logistic_torch`：四参数 logistic 曲线 $f(v) = P_{\text{lower}} + (P_{\text{upper}} - P_{\text{lower}})\cdot\sigma((v - v_{mid})\cdot k)$——**可微分**，梯度能从功率输出穿过曲线流回风速输出，两个头被同时拉向曲线两侧；
- 曲线参数来自 `sdwpf_meta.json` 的 `power_curves`：**逐机组、只用训练段拟合**（第一章 P2 的同一思想，这里作为先验知识复用——6 台训练样本不足的机组用全场回退曲线，meta 里的 `global_fallback` 就是干这个的）；
- 只在功率掩码与风速掩码**同时有效**的格子计（`both` 掩码）——任一头的目标被闸门排除，该格不产生一致性梯度；
- 除以额定功率归一化，量纲与 MSE 项可比，λ 的扫描才有统一尺度。

### 尾流损失（`pin.py` 的 `_loss_terms`）

$$L_{\text{wake}} = \frac{1}{|\mathcal{R}|}\sum_{i\in\mathcal{R}} \big\| A^{\text{learned}}_{i,:} - A^{\text{prior}}_{i,:} \big\|^2$$

> **待统一口径**：上式按有效机组行的平方距离求均值；当前代码再除以矩阵列数 134，计算的是有效行内各元素的均方。本版 W0 为 `weak`，主实验设置 λ_wake=0，暂不受影响。若将来启用尾流损失，须先确定公式与实现，再重新扫描 λ_wake。

- $A^{\text{learned}}$ 是 `agcrn_lite` 骨干**自适应学出的邻接矩阵**（node 嵌入相乘生成，3.5 节）；
- $A^{\text{prior}}$ 来自 `wake.py` 的训练段标定：按 8 个风向扇区分别统计"谁在谁的上风向"（几何 + 风向频率），逐扇区行归一化，再按训练段风向出现频率加权平均成一张静态先验图，非零行重新归一化（行和=1）；
- 只对先验图非零的行（$\mathcal{R}$，即确实存在明确上游邻居的机组）计损失——先验没有意见的行不受约束；
- λ_wake=0 时该项严格为零，先验矩阵根本不会被加载（`_load_wake_prior` 第一行就 return）。

## 4.4 四变体：消融 = 把 λ 逐个拨回 0

`pin.py` 末尾的机制非常轻：

```python
VARIANTS = {
    "ours":            {"lambda_consist": 0.1, "lambda_wake": 0.1},
    "ours_no_consist": {"lambda_consist": 0.0, "lambda_wake": 0.1},
    "ours_no_wake":    {"lambda_consist": 0.1, "lambda_wake": 0.0},
    "barest":          {"lambda_consist": 0.0, "lambda_wake": 0.0},
}
```

`_register_variant` 为每个组合动态生成一个子类并注册（构造参数可被配置 JSON 覆盖）。四个注册名**共享全部代码路径**，只有两个标量不同。

**消融的方法论读法**（每对比较回答一个问题）：

| 比较 | 回答的问题 |
|---|---|
| `ours` vs `barest` | 物理约束整体有没有用（总效应） |
| `ours` vs `ours_no_consist` | 一致性损失单独的贡献 |
| `ours` vs `ours_no_wake` | 尾流损失单独的贡献 |
| `ours_no_consist` vs `barest` | 只有尾流时怎样（交互检验） |

关键不变式：**λ=0 时变体严格等价于去掉该项的模型**（代码保证：λ_wake=0 不加载先验、λ_consist=0 时 consist 项为零且不参与梯度）——消融图上任何差异都只能归因于被拨掉的损失。

## 4.5 W0：预注册决策——"尾流能不能进主方法"由数据裁决

尾流损失用了"机组间几何 + 风向"这一物理知识，但它成立的前提是**这份数据里尾流效应真的可测**。`calibrate-wake`（`analysis/wake_calibration.py`）就是裁决程序：

1. 只读训练段 196 天；前 60% 训练日从 8 个风向约定中**选**，后 40% 做**确认**（选/确认分离，防止在同一个子集上既挑假设又验证假设）；
2. 检验量：上风向机组对下风机组的风速亏损（m/s）与功率亏损（% 额定），要求为正且置信区间高于零，并对照**预注册锚点**（风速 0.3 m/s、功率 2%——写进规格的"多大算显著"）；
3. 输出 `reports/wake_calibration.json` 的 `decision` 字段：`significant / weak / none / undetermined / orientation_unconfirmed`。

**本版清洗数据重新运行 W0 的结论是 weak**：确认集风速亏损 0.175 m/s（95% CI 0.146–0.203），功率亏损为额定功率的 1.232%（95% CI 1.016–1.579）。两者为正，但低于预注册锚点。按规则，**本版主实验不启用尾流损失**；后续若数据或协议改变，须重跑 W0 并按新的 `decision` 分支：

- 主实验改为**两变体**：`ours_consist_only`（λ_consist=选定值，λ_wake=0）vs `barest`；
- 图 12（学习图 vs 尾流先验对照）不进正文；
- 论文措辞："尾流证据较弱，主实验比较一致性损失的贡献"——如实、可辩护。

**这条纪律由代码执行**：`pin.py` 的 `_load_wake_prior` 在训练任何 λ_wake>0 的变体前检查 `wake_calibration.json` 的 `decision == "significant"`，并核对先验文件的风向约定与 W0 选择一致；不满足就拒绝训练。

## 4.6 W2：只在验证集上选 λ

λ_consist 是方法模型最重要的超参数，选择流程三步走，核心纪律是**测试段全程不在场**：

1. **预实验**：跑一次 λ=0.1，看训练日志（`reports/train/<run_id>.log`）里四项损失（point/wind/consist/wake）的原始量级——若某项比别的小 3 个数量级，它的 λ 候选范围就要相应放大。日志按 epoch 记录训练/验证两套四项损失，设计就是为这一步服务的；
2. **扫描**：对候选集 {0.01, 0.03, 0.1, 0.3, 1.0}（`configs/lambda_sweep_no_wake/`，弱证据路线 λ_wake=0）逐个执行

   ```bash
   python -m wpf_benchmark run --model ours \
     --config configs/lambda_sweep_no_wake/consist_0.1.json \
     --experiment lambda_sweep --validation-only --no-plots
   ```

   `--validation-only` 让 runner 在训练+验证评估后**直接返回，不读测试段**——扫描代码路径上测试数据从未被加载，泄漏在流程上不可能发生；
3. **选择**：按预注册规则"**验证 MAE 为主、直接一致性误差为辅**"定 λ，写进 `configs/ours_consist_only.json`，配置自此冻结。"为辅"的含义：验证 MAE 接近的两个 λ 之间，选一致性误差小的那个——物理收益是次级目标，不与精度冲突时才追求。

## 4.8 与导师讨论的问题预案

**Q1：一致性损失会不会只是一个花哨的正则化？**
形式上它就是正则项（加权加进损失），但与普通正则（L2、dropout）的区别在于**约束来自物理规律而非统计先验**：它惩罚的具体方向由功率曲线指定（"你的功率-风速组合违反了这台机组的物理特性"），因此改进应集中在 D 层违背率和高风速分箱（功率曲线最陡、违反代价最大处）——如果实验观察到这种**定向**改进，就区别于无差别平滑的正则。这是论文里论证"物理信息有用"的关键实验设计。

**Q2：本版 W0 是弱证据，这个方法是不是就失败了？**
不是。尾流部分按当前实测标注 `weak`，本版主实验不启用尾流损失；一致性损失不依赖 W0 裁决，仍可按预先规定的流程评估。后续不能把旧数据或旧版 W0 的 `weak` 当作新版本的验收答案。

**Q3：风速辅助任务的贡献和一致性损失的贡献怎么分开？**
四变体的网络结构完全相同（都有风速头），λ 权重是唯一变量，所以四变体内部无法分离"辅助任务本身"的贡献。分离要靠两级对照链：**`barest` vs 基线 `agcrn_lite`**（同骨干、同训练纪律，差异是 barest 多一个风速输出头及其 MSE）→ 这一对检验辅助风速任务；**`ours_consist_only` vs `barest`**（结构完全相同，差异是 λ_consist）→ 这一对检验一致性损失。论文架构的 `agcrn` 只作为独立模型比较。

**Q4：λ 扫描只在验证集做，测试结果会不会对 λ 敏感到不可信？**
看图 10 的形状：若 MAE 对 λ 在一个量级跨度内平坦（典型情形），结论对 λ 稳健；若出现尖锐最优，则报告敏感性并讨论。这正是图 10 存在的目的——把超参数的敏感性本身作为结果呈现，而不是藏起来。

**Q5：为什么曲线参数用 meta 里拟合好的，而不是让网络端到端学曲线？**
三个理由：① 功率曲线是**这台机组已知的物理属性**，训练段有大量稳态观测可直接拟合（R²>0.9），没有理由让网络重学；② 固定曲线使一致性损失的梯度全部流向网络（若曲线也学，损失可以被"把曲线学歪"来逃避）；③ meta 的曲线只用了训练段，与协议防泄漏条款一致。

## 5.1 管道设计：图件是"读结果的报表"，不是手工劳动

`plots` 命令的设计原则有三条，每条都服务于"实验反复跑、图件随时新"：

1. **结果自动发现**：每次 `run` 向 `reports/eval/index.jsonl` 追加模型、表、种子、配置、实验类型和数据/代码版本摘要。图件生成器只聚合与当前数据和代码版本一致的记录；常规主图读取 `standard`，并纳入 W3 `ablation` 中最终的 `ours` 与 `barest`，其他消融变体只进图 9。同模型同配置的多种子由图表端汇总，表 1 当前只输出均值。
2. **缺料跳过、不缺料全出**：某图需要的输入不存在时打印 `SKIP figXX: 原因` 继续跑别的。这是为渐进式实验设计的——轻量基线刚跑完就能出图 2/3/6/7/13，深度实验补上后 `plots --all` 一刷全部就位。
3. **预测数组随 run 存档**：`run` 默认保存 `<run_id>_arrays.npz`（预测、真值、资格掩码、实测风速、限电掩码、发布时刻功率等，全部 `(T_eff, N, H)` 三维）——案例图（图 5/8/11）的原料。重画图不必重跑模型。

**样式一致性**（`style.py`）：每个模型登记固定颜色和英文显示名（`MODEL_STYLE`），未登记的按名字哈希得稳定备用色——全文所有图的"persistence 永远是同一个灰、你的方法永远是同一个强调色"由此保证。画面文字为英文（投稿要求），PDF 内文字保留可编辑字体。

## 5.6 与导师讨论的问题预案

**Q1：图 6 里模型在短视野输给 persistence，论文怎么写？**
如实写并解释：10 分钟尺度自相关极强，任何模型的短视野提升空间都有限；价值在长视野（60–120 分钟）的领先——这正是"模型学到了 persistence 不可能有的结构"的表现。配合图 11（爬坡段）说明短视野的"抄数"在突变时刻是灾难，平均意义上的平局掩盖了风险差异。

**Q2：案例图（5/11）会不会变成 cherry-picking？**
防挑样本的做法：图 5 的"典型日/爬坡日/限电日"按预定义规则挑选（B 层分块与 C 层爬坡清单），不按模型表现挑；正文明确挑选规则；案例图只作直观补充，定量结论永远以表 1 和图 6/7/13 为准。

**Q3：图这么多，投稿版面放不下怎么办？**
优先级已内建：表 1 + 图 6 + 图 13 是"更准/有结构/合物理"三主张的最小集；图 7/8/11 进正文或附录视版面；图 9/10 是方法论文的必备消融证据，不可裁。多余的图正是 supplementary material 的天然内容。

**`run` 的通用参数**（所有模型通用，记住五个就够）：

| 参数 | 作用 | 什么时候用 |
|---|---|---|
| `--model` | 注册名 | 必填 |
| `--config` | 配置 JSON（protocol + model 参数 + seed） | 必填 |
| `--repeat 3` | 依次用 seed, seed+1, seed+2 跑三遍 | 深度模型必加 |
| `--seed 5` | 覆盖起始种子 | 复现指定运行时 |
| `--validation-only` | 训练+验证后直接返回，**不碰测试段** | λ 扫描（W2）必加 |
| `--experiment 名字` | 给结果打实验标签（ablation / lambda_sweep...） | 图 9/10 靠它筛选 |
| `--no-plots` | 跑完不自动刷图件 | 批量跑时加，最后统一 plots |
| `--no-save-arrays` | 不存 NPZ 预测数组 | 只关心指标时省磁盘 |

# 附录 A 本版修复与复现状态（2026-09-27）

## A.1 代码与协议修复

1. **缺口填补**：`fill_short` 对连续缺失的前 3 步仅用缺口前最后一个有限值；第 4 步起留给同一时刻的空间 kNN。序列开头没有前值时直接走空间填补。该规则按当前已经连续缺失的步数执行，不需要事先知道缺口最终长度。原来的双端时间线性插值只保留在离线 k 标定比较中，不进入预测输入。
2. **训练段统计**：清洗 P2 参照曲线、整机和风速箱残差 MAD 阈值均只在前 196 天估计，再固定用于后续数据；`calibrate-k` 也只用训练段。两种遮掩场景的新标定都支持 `k=12`。特征填补的空间邻机值只取同一时刻，不读未来时刻。
3. **场站与爬坡口径**：场站 MAE/RMSE 汇总每格有效机组误差；场站 NMAE 按各格有效机组总额定容量归一化。SS 仅单机级。爬坡采用逐格判别并显式输出阳性格数，未声称独立事件数。

对应回归测试覆盖短缺口因果性、长缺口转空间填补、训练段阈值冻结、场站动态容量分母与逐格爬坡字段。
