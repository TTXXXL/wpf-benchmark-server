# 阶段2：一次C诊断训练与交付

目标：取得可重现推理的模型权重和原始分辨率输入，再导出低功率概率q、低功率分支和正常分支定位问题。这里不修改模型结构、损失权重或评分规则。

## 需要训练几次

- 有原C权重：不训练，直接打包原运行。
- 没有原C权重：只补一次C，默认种子1，保持原配置。种子1用于检查阶段1发现的高误差，不是挑选最佳模型。
- 新训练模型的内部输出只能解释新运行，不冒充原40次训练的内部证据。先核对新预测是否复现原事件和误差形态。
- 暂不重跑ABC×5或40次矩阵。后续改动在验证段筛选，五种子确认另开阶段。

## 服务器直接执行

在现有服务器项目根目录、原来的Python/PyTorch环境中运行。该目录应包含src/、configs/、data/、reports/、scripts/。保留原服务器的data/processed/与reports/，更新代码不需要重新预处理。

```bash
git pull --ff-only
python scripts/stage2_delivery.py check
```

check会核验原40次运行的两份冻结处理文件，并列出reports中找到的权重。原数据指纹应为033fb4a7a9e0daf8。文件SHA与原清单不符时停止，先恢复原快照；不要运行preprocess或fit-power-curve去覆盖它。

没有原权重时，执行这一个命令：

```bash
python scripts/stage2_delivery.py run --seed 1
```

脚本只在没有同批已完成诊断结果、也没有按原种子1运行ID命名的原权重时训练一次；训练结束自动打包。如果已有完成结果则收集交付，不重复训练。正常输出最后出现DELIVERY: ..._delivery.zip。

实际调用的训练命令为：

```bash
python -m wpf_benchmark run --model agcrn_lite --config configs/agcrn_lite_low_power_mae.json --seed 1 --repeat 1 --tag stage2_C_s1 --experiment stage2_internal_20261009 --target-mask m1 --eval-mask m1 --save-checkpoint --save-arrays --no-plots
```

这是原C配置、M1训练和主评分，Day 1–196训练，197–221验证早停，222–245诊断测试。没有validation-only，因为需要检查阶段1已发现的测试事件；测试仅用于机制诊断，不用于挑选新模型或阈值。

## 有原权重时如何交付

若原权重位于reports/checkpoints/lite_low_power_20261008_154523_133224_best.pt，run命令会直接收集原种子1结果，不训练。

若权重另存在其他路径，执行下面命令，将末尾路径换成实际文件：

```bash
python scripts/stage2_delivery.py collect --run-id lite_low_power_20261008_154523_133224 --checkpoint /实际路径/原C种子1权重.pt
```

这个命令只有权重路径需要填写。原权重文件必须对应该run-id；若旧文件未记录规范checkpoint校验和，交付清单会明确标记“用户提供，待推理核验”，分析时首先核对能否复现原NPZ，不先认定二者对应。

## 发回什么

只发自动生成的reports/stage2/*_delivery.zip。它包括：

1. model_best.pt：最佳权重；新格式文件内含归一化、特征/机组顺序、配置和训练来源。
2. run/：同次运行的预测NPZ、main/all指标JSON、训练日志，以及新运行的控制台日志。
3. inputs/sdwpf_inference_slice.parquet：Day 196–245的完整机组时间网格，覆盖验证、测试和前置历史。不要自行删掉掩码无效行、非静风行或只保留532格。
4. inputs/sdwpf_meta.json：原元数据；推理使用checkpoint中的训练归一化，不能在数据切片上重新拟合。
5. recipe/与code/：C配置和当前推理源码，便于重建模型。
6. delivery_manifest.json：原完整处理文件指纹、交付文件哈希、种子、来源运行、数据切片范围及环境。

整个处理文件不需要上传；程序已保留原完整文件身份，并打包足够的推理输入。原CSV在本地已经按SHA核验相同，通常不需要重复上传。权重、数据、日志和ZIP均不提交GitHub。

## 收到后分析什么

先加载权重补推理并核对最终预测与同次NPZ一致，再保存state_logits、q、低/正常分支、最终预测及对应时间/掩码，检查：

- 129、130号机组的M1静风事件，尤其10→120分钟高估增长。
- 真实低功率和非低功率的q分布、两分支幅度与混合贡献。
- 起报功率10–200 kW的h=1退化及<10 kW收益对照。
- 65号机组M2新增输入质量异常事件，单独报告。
- 验证段的对应现象，为下一项改动提供验证段证据。

如果check失败或训练失败，不继续后续步骤；将终端错误和reports/stage2/stage2_C_s1.console.log发回。失败的运行不能视为完成。
