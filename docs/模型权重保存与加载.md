# 模型权重保存与加载

从本功能版本开始，`run` 默认在训练结束后保存验证指标最优的一轮权重，随后才进行测试预测。`--validation-only` 也保存权重；`--repeat` 的每次运行各自保存，不覆盖其他种子。

支持所有现有 PyTorch Forecaster：`agcrn`、`agcrn_lite`（含低功率头）、`lstm_seq2seq`、`patchtst`，以及 PIN 系列 `ours`、`ours_no_consist`、`ours_no_wake`、`barest`。持续性、线性和 GBDT 等非 PyTorch 模型不生成 `.pt`。

## 训练命令

在已准备好清洗数据的服务器项目根目录执行下面的命令，新增一次 C 配置诊断运行：

```bash
wpf-benchmark run --model agcrn_lite --config configs/agcrn_lite_low_power_mae.json --tag C_checkpoint --experiment checkpoint_diagnostic_v1 --seed 0 --save-checkpoint --save-arrays --no-plots
```

只训练和记录验证结果、不读取测试段：

```bash
wpf-benchmark run --model agcrn_lite --config configs/agcrn_lite_low_power_mae.json --tag C_checkpoint_val --experiment checkpoint_validation_v1 --seed 0 --repeat 3 --validation-only --save-checkpoint --no-plots
```

`--save-checkpoint` 是默认行为，原训练命令不加此参数也会保存。需要关闭时使用 `--no-save-checkpoint`，它与 `--no-save-arrays` 相互独立。

开发版未安装包到解释器时，用兼容项目 `.runtime` 的 Python 3.12 将上述 `wpf-benchmark` 换成下面的入口，后面的参数保持相同：

```bash
python -c "import sys; sys.path[:0]=['.runtime','src']; from wpf_benchmark.cli import main; raise SystemExit(main())" run --model agcrn_lite --config configs/agcrn_lite_low_power_mae.json --tag C_checkpoint --experiment checkpoint_diagnostic_v1 --seed 0 --save-checkpoint --save-arrays --no-plots
```

## 保存位置与内容

```text
reports/checkpoints/<run_id>_best.pt
reports/train/<run_id>.log
reports/eval/<tag>_main_<timestamp>.json
reports/eval/<tag>_all_<timestamp>.json
```

验证专用运行只生成 `validation` JSON。JSON 的 `checkpoint` 字段记录项目根目录相对路径、文件 SHA256 和格式版本；关闭保存或非 PyTorch 模型时为 `null`。训练日志与 CLI 输出也记录保存位置。40 次批跑和旧 M1 批跑会将新结果声明的权重纳入完成文件核验；40 次套件还将其纳入每个任务的文件哈希清单。已有不含该字段的历史结果仍可读取。

`.pt` 包含 CPU 上的 `state_dict`、完整模型构造参数、ProtocolConfig、特征顺序、训练归一化参数、机组顺序、最佳轮验证指标，以及 run_id、种子、experiment、数据/代码/配置指纹。PIN 还保存功率曲线和已使用的尾流先验。文件先写入同目录临时文件，再原子替换目标，写入失败不会损坏已有权重。

选择标准沿用原训练流程：普通深度模型按验证 MSE，配置 MAE 的 AGCRN/Lite 按验证功率 MAE；Lite 分类辅助总损失不参与替代早停指标。PIN 按原验证 point MSE 选择。保存的是训练循环恢复的最佳轮，**不是最后一轮**。

## 无需重新训练的加载

以下代码需将 `<run_id>` 替换为结果 JSON 中的实际值。在已安装本项目的环境运行；开发版先添加 `.runtime` 和 `src` 到 `sys.path`。

```python
from wpf_benchmark.models.checkpoint import load_checkpoint

model = load_checkpoint("reports/checkpoints/<run_id>_best.pt", device="cpu")
print(model.name, model.model_config)
print(model.validation_metrics)
print(model.checkpoint_metadata)
print(model.turbine_ids)
```

加载会恢复网络为 `eval()` 模式，并严格检查权重键和形状。可以传 `device="cuda"` 在可用 GPU 上推理。加载本身不读取原始 CSV、Parquet 或 `sdwpf_meta.json`，不会调用 `fit()` 或重新拟合 scaler。后续预测应保持机组顺序与 `model.turbine_ids` 一致、特征顺序与 `model.features` 一致。

已有物理单位历史数组 `histories_physical` 时，形状须为 `(B, N, F, input_window)`，随后使用保存的 scaler：

```python
histories = model.scaler.transform_histories(histories_physical)
forecasts_kw = model.predict_batch(histories)  # (B, N, horizon)，单位 kW
```

直接调用 `fit()` 的 Python 用户可在成功训练后调用 `model.save_checkpoint(path, metadata={...})`。加载使用当前 PyTorch 可用的 `weights_only=True` 模式；旧 PyTorch 兼容读取，仅应加载本项目生成且来源可信的文件。

## 与当前实验的关系

- 原 40 次训练未保存权重，已有预测 NPZ 不能反推出原模型权重。新功能不能补回它们；重新训练属于新的运行。
- 补做诊断时核对原实验的数据指纹；不要用另一个清洗版本冒充原实验输入。新权重保存代码会改变代码指纹，冻结批跑必须使用新的 `--experiment` 名称。
- 保存发生在 `fit()` 成功完成之后。训练中途失败没有本次完整权重；本文件不包含优化器、随机数或训练进度状态，不能用于断点续训。
- 当前未新增低功率概率/分支诊断数组的自动导出；加载后的 Lite 网络保留 `return_aux=True` 接口，可供下一步诊断工具使用。
- 权重属于运行产物，位于已被 `.gitignore` 排除的 `reports/`。服务器同步和上传 ZIP 不包含已有权重，GitHub 也不提交权重。需要下载服务器权重时，应单独保存对应 `.pt` 与结果 JSON、日志。

开发验证覆盖最佳轮选择、各骨干和低功率分支的加载预测一致性、PIN 曲线恢复、验证专用多种子保存、关闭保存的预测一致性、原子写入失败和批跑文件完整性。
