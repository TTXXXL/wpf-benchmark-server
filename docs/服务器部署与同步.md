# 服务器部署与开发版同步

## 目录职责

wpf-benchmark/是唯一开发版。代码、配置、说明先在这里修改，用已有.runtime/和tests/验证。wpf-benchmark-server/是生成的上传副本，不直接改其中的代码。

服务器副本与ZIP包含src/、configs/、必要训练脚本、六份主题说明及索引、安装文件和两份SDWPF原始CSV。处理Parquet与元数据由服务器首次部署时生成，不随ZIP分发。.runtime/、tests/、reports/、scripts/local/和docs/local/仅在开发版保留。

scripts/和docs/采用明确白名单。诊断、复评分、bootstrap和阶段性验证交付脚本不进入服务器副本、ZIP或Git。artifact_checks.py是训练批跑所需的函数模块，保留结果身份与对齐检查。

## 首次部署

上传wpf-benchmark-server.zip并解压，进入项目目录，在Python3.8–3.12环境执行：

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[deep]'
wpf-benchmark preprocess
wpf-benchmark fit-power-curve
wpf-benchmark eval selftest
wpf-benchmark models
```

纯Git新clone需要自行放入两份原始CSV；Git不包含数据。需要GBDT时另装对应后端，见[使用指南](使用指南.md)。

## 更新已有服务器

激活原来的Python环境，在项目根目录执行：

```bash
git pull --ff-only
```

保留原data/processed/和reports/；不因代码或文档更新而重新preprocess、fit-power-curve或重跑已完成实验。已有批次有冻结指纹，更新代码后不可直接续跑旧版本批次。按需重跑入口见[批跑说明](低功率40次统一重跑.md)。

采用ZIP更新时，先解压到暂存目录，再更新代码、配置、脚本与文档，保留服务器上的数据、报告和Python环境。新的生成副本不包含旧诊断脚本；离线复核统一在本地开发版进行。

## 本地验证、同步与提交

完成开发版验证后运行：

```bash
python scripts/sync_server_project.py
python scripts/sync_server_project.py --check
```

同步会刷新服务器副本和同级ZIP，按旧同步清单移除不再分发的文件，并检查目录、文件哈希及ZIP内容。新增服务器训练脚本或主题文档时，应明确加入同步脚本白名单；本地验证工具无需加入。

同步核验后，在服务器版Git仓库提交并推送：

```bash
cd ../wpf-benchmark-server
git add -A
git diff --cached --name-only
git commit -m "Sync server project"
git push origin main
```

提交前确认没有数据、报告、ZIP、测试夹具或local目录。Git中允许保留.gitkeep目录占位及同步清单。不要删除或重建服务器已有处理快照来满足新的校验结果。
