# 服务器部署与本地同步

## 两份项目分别做什么

- `wpf-benchmark/` 是本地开发版。代码在这里修改，使用已有的 `.runtime/` 和 `tests/` 验证。
- `wpf-benchmark-server/` 是自动生成的服务器版。上传其目录，或上传同级的 `wpf-benchmark-server.zip`。
- 服务器版包含程序 `src/`、实验配置 `configs/`、运行脚本 `scripts/`、安装文件、手写说明 `docs/`，以及 `data/` 中的两份原始 CSV。清洗后的 Parquet 和元数据在服务器上生成，不随目录或 ZIP 分发。它不包含本地 `.runtime/`、测试夹具、笔记本，以及 `reports/` 中已生成的结果。`.gitkeep` 仅用于保留目录。

服务器版是从开发版同步出来的，不要直接在服务器版的本地副本中改代码。服务器运行产生的数据和报告只保存在服务器上；下次上传代码时，先备份服务器上的实验结果。

## 第一次上传并运行

已经完成40次低功率实验、准备开展内部输出诊断时，直接按[阶段2：一次C诊断训练与交付](阶段2_一次诊断训练与交付.md)执行。该流程保留原处理数据和报告，核验原冻结快照后最多补跑一次C并打包交付；不重复执行下面的新部署预处理步骤。

把 `wpf-benchmark-server.zip` 上传到服务器并解压，进入 `wpf-benchmark-server/`。压缩包包含 SDWPF 原始 CSV；不包含清洗结果。然后在服务器的 Python 3.8 至 3.12 环境运行：

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[deep]'
wpf-benchmark preprocess
wpf-benchmark fit-power-curve
wpf-benchmark eval selftest
wpf-benchmark models
```

手动准备新部署时需要运行 `preprocess` 来生成 Parquet 与元数据；`fit-power-curve` 将训练段功率曲线写入元数据，供方法模型使用。`.[deep]` 安装深度模型使用的 PyTorch；`pyarrow` 已在项目依赖中。若服务器需要运行 GBDT，再执行 `python -m pip install -e '.[gbdt]'`。模型和方法配置集中在 [模型与消融](模型与消融.md)。评估 JSON、论文图件及训练报告会在服务器运行后写入 `reports/`。

若准备本轮 40 次实验，可以改用 [批跑入口的 `--prepare`](低功率40次统一重跑.md)一次完成数据准备和自检；手动完成以上准备后则不再传 `--prepare`。

## 后续修改怎样同步

在本地开发版 `wpf-benchmark/` 中完成修改并用现有 `.runtime/` 验证后，运行：

```bash
python scripts/sync_server_project.py
python scripts/sync_server_project.py --check
```

脚本会刷新同级的 `wpf-benchmark-server/` 和 `wpf-benchmark-server.zip`，同步两份原始 CSV，并移除服务器副本中的清洗后 Parquet 与元数据；不会复制 `.runtime/`、测试和已生成的报告。上传新的 ZIP 即可。若服务器上已有训练报告或新的数据文件，部署前先备份，并保留服务器的 `reports/`；不要直接清空服务器上的整个项目目录。

GitHub 仓库只跟踪服务器版的代码、配置和说明；`.gitignore` 排除原始数据、清洗结果与运行报告。每次本地验证并同步后，在服务器版仓库中提交本次差异，以便追溯上传版本。

```bash
cd ../wpf-benchmark-server
git add -A
git commit -m "Sync server project"
git push origin main
```

提交前用 `git status` 核对变更；`data/raw/`、`data/processed/` 和 `reports/` 不应出现在提交文件列表中。上传 ZIP 与同一次同步产生的提交对应，便于按提交记录追溯代码版本。
