# 评估与结果分析

本文统一说明评分口径、时间对齐、指标、配对统计和图件。可执行定义在 [ProtocolConfig](../src/wpf_benchmark/evaluation/config.py)、[掩码规则](../src/wpf_benchmark/data/masks.py)和 [Evaluator](../src/wpf_benchmark/evaluation/evaluator.py)。

## 1. 目标与评分口径

新运行只提供 M1、M2 两种目标口径，默认训练与主表评分均为 **M1**。两者独立设置，掩码作用于预测目标时刻 `t+h`；模型输入继续使用因果清洗后的历史特征。

| 口径 | 有效目标 | 评分真值 |
|---|---|---|
| M1（默认） | 清洗后 `Patv` 有限，六个原有质量/工况 flag 均为假，且 `o_bad` 为假 | 清洗后 `Patv` |
| M2 | 原始 `Patv` 和 `Wspd` 均有限，且 `o_bad` 为假；不使用原有 flag | `Patv_obs = max(原始 Patv, 0)` |

`o_bad` 是三类原始观测规则的并集：任一桨距角 `Pab1/2/3 > 89°`；`Patv ≤ 0` 且 `Wspd > 2.5 m/s`；`|Ndir| > 720°` 或 `|Wdir| > 180°`。阈值是严格大于，判定在风向回绕、缺失填补和功率清洗之前完成。M2 使用原始功率真值，因为它可能重新纳入清洗时标为离群并填补的格。规则依据为 [SDWPF 数据论文](https://www.nature.com/articles/s41597-024-03427-5) 的异常观测建议；本仓库指标不等于赛事官方评分。

历史 M0 只用于识别旧结果和验证 M1 的基础闸门，**不能在新运行的命令行或配置中选择**。旧 Wave 1 JSON/NPZ 保持历史口径，不能将其数字标成 M1。旧结果可继续用 `scripts/official_mask_rescore.py` 进行历史诊断；该脚本拒绝新 M1/M2 结果。

### 使用

本轮 40 次与旧 M1 41 次套件的区别、准备与续跑见 [批跑说明](低功率40次统一重跑.md)。

旧清洗数据缺少官方规则列时，在新批次准备阶段从原始 CSV 重新生成：

```bash
wpf-benchmark preprocess
wpf-benchmark fit-power-curve
wpf-benchmark eval selftest
```

默认运行：

```bash
wpf-benchmark run --model barest --config configs/barest.json --experiment mask_tm1_em1 --no-plots
```

训练口径和评分口径可独立指定；配置文件 `protocol.target_mask`、`protocol.eval_mask` 也接受 `m1`、`m2`，命令行优先：

```bash
wpf-benchmark run --model barest --config configs/barest.json --target-mask m2 --eval-mask m1 --experiment mask_tm2_em1 --no-plots
wpf-benchmark rescore --run-id <已保存的M1或M2运行ID> --eval-mask m2 --experiment mask_tm1_em2
```

`rescore` 复用预测数组，不重新训练；只接收新 M1/M2 运行，并核对测试网格、原评分口径的真值与有效位、发布时刻功率和风速。输出新 main/all JSON、新 NPZ 和索引条目。训练日志首行与 JSON `target_counts` 记录训练及验证有效格数；`mask_sensitivity` 在同一预测数组上同时给出 M1/M2 的 MAE、RMSE、持续性基准和 skill。

### 论文比较

M2 和 M1 的真值及样本集合不同，跨口径裸 MAE 不能用来判断模型优劣。比较**训练目标口径**时，固定同一 `eval_mask`、同一测试网格和种子；比较**评分口径的敏感性**时，固定预测数组并同时列出 `n` 和各自持续性基准。`all` 附表仍使用原来的清洗后 `Patv` 有限条件，仅作宽松参考。当前自检参考集中在第 4 节。

功率曲线、尾流标定仍沿用历史基础质量 flag 的训练段拟合规则；PIN 的风速监督掩码不随功率目标口径变化。旧 M0 的 4,948,656 格与 66.46 kW 仅用于识别历史结果，不能作为 M1 的验收值。

## 2. 时间轴与预测数组

默认 Day 1–196 训练、197–221 验证、222–245 测试；步长 10 分钟，输入 144 步，预测 H=12 步。预测、真值及评分掩码统一为 `(T_eff,N,H)`，`T_eff=T_test-H`，134 台机组按同一 ID 顺序对齐。

样本 t 的数组列 `h-1` 对应目标 t+h，h=1…H。取真值的切片是 `P[h:T_test-H+h]`。首个样本的历史可以来自测试之前的训练/验证段，但只读取发布时刻及此前数据。时间划分保持连续，随机种子不改变数据分区。

评分单元是发布时刻 × 机组 × 时距；同一机组目标时刻可重复被不同发布时刻预测。报告群体规模时分开记录评分单元数与去重目标数。日聚合需要明确按发布日还是目标日；低风速诊断按实际发布日午夜切分，日电量按下述 h=1 目标日计算。

## 3. 指标与默认阈值

设有效单元误差为 `e=预测−真值`，MAE 为 `mean(abs(e))`，RMSE 为 `sqrt(mean(e²))`，单机 NMAE 为 `100×MAE/1550`。SS 为相同有效群体上的 `100×(1−模型MAE/持续性MAE)`；持续性 MAE 为零时 SS 未定义。

| JSON 字段 | 定义与注意事项 |
|---|---|
| `A_turbine` | 有效单元 MAE/RMSE/NMAE、持续性 MAE 与 SS |
| `A_farm` | 按相同有效机组集合求和；有效机组占比至少 0.85，NMAE 按实际入选机组容量归一化 |
| `B_per_horizon` | 每个时距独立使用该时距真值、预测和掩码 |
| `B_wind_bins` | 目标时刻实测风速分箱 `[0,3)、[3,6)、[6,9)、[9,12)、[12,15)、[15,40)`；用于事后诊断 |
| `B_bias`、`B_stability` | ME、高估/低估比例及按 7 天发布时段的误差块 |
| `C_ramp` | 与发布时刻功率相比，绝对变化至少 155 kW 的逐单元 precision/recall/F1；不合并为独立爬坡事件 |
| `C_daily_energy` | 仅 h=1 预测，每个 10 分钟目标计一次；功率求和除以 6000 得 MWh，边界日可能不完整 |
| `C_high_wind` | 目标风速至少 18 m/s；100 个以内有效单元仅提示样本不足 |
| `D_physics` | 与训练段风速分箱中位数曲线偏离超过 3σ 的比例、真实值参照、曲线覆盖率及输出越界率 |
| `E_probabilistic` | 当前为 null，占位，尚未实现概率预测评分 |

评估曲线只从训练段拟合，默认风速箱宽 1 m/s、至少 30 个样本，残差尺度为稳健 MAD。评估查曲线时使用未来实测风速，不能将这个诊断指标作为预测输入能力。曲线违背率分母为全部有效评分单元，另报曲线覆盖率；同时检查 MAE 与真实值违背率。

`ramp_window_steps=6` 是预留参数，当前逐单元爬坡判别不使用它；`cut_in=3/cut_out=25` 也不自动改变主表掩码。阈值和窗口的完整列表由 ProtocolConfig 保存到结果 JSON，不再维护另一份手写 dataclass。

空群体统计在 JSON 中为 null，含义是无定义，不能当作误差为零。原始负功率可能包含自耗电，当前非负目标和预测越界指标应按本协议解释。

## 4. 自检与当前回归参考

```bash
wpf-benchmark eval selftest
```

| 默认口径 | 有效评分单元 | 持续性 MAE / RMSE（kW） |
|---|---:|---|
| M1 | 3,188,016 | 约 99.83 / 165.89 |
| M2 | 3,636,220 | 约 104.95 / 173.09 |
| all 宽松附表 | 5,537,952 | 仅作宽松参照 |

[selftest.py](../src/wpf_benchmark/evaluation/selftest.py)允许格数相对偏差 0.1%；M1 MAE 范围 99.7–100.0、M2 104.8–105.1 kW，两个 RMSE 允许绝对偏差 0.01 kW。还检查 SS=0、持续性爬坡 recall=0/precision 未定义、非空场站汇总和官方规则重叠数；M1 真实值曲线违背率约 1.0–1.2%，持续性约 25.8–26.2%。验收适用于当前 SDWPF 清洗快照及默认协议，不是任意新数据的常数。

## 5. 结果文件与版本核验

主表/附表 JSON 记录 protocol、model_config、输入特征、种子、实验标签、code_digest/data_digest、训练计数、验证指标及耗时。正式比较前同时核验配置、损失、目标/评分口径、时间网格、机组顺序和真值/掩码，不能只比较相同模型名下的 MAE。

NPZ 保存 `forecasts/truth/valid/ramp_mask/wind_speed/curtail_mask` 的三维网格、`last_power` 的 `(T_eff,N)` 网格、`turbine_ids` 和 `times`。`times` 是全部测试时刻的 int64 纳秒时间偏移，长度 `T_eff+H`；新 M1/M2 运行还保存各自的 `truth_m1/valid_m1/truth_m2/valid_m2`。

同一注册名可以对应不同损失、锚点或状态头。尤其本轮 A/B/C 均为 `agcrn_lite`，必须用 tag、完整配置和唯一 run_id 区分。严格清单、数组逐元素对齐、原始标签审计、版本取证与历史群体诊断见 [离线诊断说明](../scripts/review_diagnostics/README.md)。这套核验会拒绝缺种子、重复种子与混用指纹。

## 6. 配对检验

`scripts/paired_bootstrap.py` 读取评估索引、主表 JSON 和预测数组 NPZ；只依赖 NumPy 与 Python 标准库。它不会训练模型，也不会读取其他实验标签的运行。所有选中的运行必须具有相同的测试时间、机组顺序、有效位和真实值，并且必须保存了 `*_arrays.npz`。

### 自动发现模型

在项目根目录运行：

```bash
python scripts/paired_bootstrap.py --eval-dir reports/eval \
  --experiment ablation --out reports/paired_ablation
```

脚本读取该实验标签下的所有 `main` 运行，按模型名排序，并为每两个模型生成一个比较（`C1`、`C2`……）。默认比较方向是排序后的前一个模型减后一个模型；`delta < 0` 表示 A 的误差较小。
通用入口省略 `--experiment` 时使用 `standard`；第一波预设省略时使用 `wave1`。

### 指定模型、方向和种子数

```bash
python scripts/paired_bootstrap.py --eval-dir reports/eval \
  --experiment ablation --out reports/paired_ablation \
  --models ours,barest --pair ours:barest \
  --expect-seeds ours=3 --expect-seeds barest=3 \
  --n-boot 10000 --boot-seed 20260929
```

- `--models` 限定读取的模型；不写 `--pair` 时，按照这里给出的顺序生成全部两两比较。
- `--pair A:B` 指定方向 `M(A) − M(B)`；可重复使用。若只写 `--pair`，脚本仅加载这些配对涉及的模型。
- `--expect-seeds MODEL=N` 可重复使用，只检查数量并发出 warning，不会限制实际使用的种子。未指定时不假设种子数。
- `--output-prefix NAME` 可改变报告文件名。通用入口默认写 `paired_summary.json` 和 `paired_summary.md`。

同一模型、同一种子出现多条运行记录时，以索引中 `created` 最新的一条为准，并在报告中列出被舍弃的 `run_id`。某个指定模型缺失时会写 warning；涉及它的比较会跳过。

报告包含整体、各预测步长和发布时刻功率档的 MAE/RMSE 比较，以及日块 bootstrap 和“日块 + 种子”bootstrap 的区间。只有两个模型都具有多个种子且种子标签有交集时，才另列相同标签的种子差值；相同数字标签本身不证明模型初始化逐位相同。

### 第一波预设

原命令保持原来的固定模型、P1–P8 比较、预期种子数和 `wave1_paired_summary.*` 文件名：

```bash
python scripts/wave1_paired_bootstrap.py --eval-dir reports/eval \
  --experiment wave1 --out reports/wave1_paired
```

通用入口也可用 `--preset wave1` 调用这一预设。原脚本若加 `--models`、`--pair` 或 `--expect-seeds`，则自动切换到通用模式。

### 与本轮 40 次结果的关系

上面的通用 bootstrap 入口按注册模型名发现运行，不能自动区分同名 Lite 的 A/B/C 或多个锚点配置。其“缺种子 warning、重复 seed 选最新”的规则也不能替代本轮严格验收。先使用 [本轮分析清单与专用入口](低功率40次统一重跑.md)得到配对五种子比较，再以明确的运行清单扩展时间块不确定性分析。

种子 SD 描述训练随机性，时间块 bootstrap 描述测试时段的不确定性。按同一时间块同时保留所有机组与时距，不把评分单元当作独立样本；块长需有明确依据并报告敏感性。既有测试段已参与诊断，机制或收益的确认仍需独立时段。

## 7. 论文图件

每次 `wpf-benchmark run` 完成后会自动刷新图表；也可在项目根目录单独运行 `wpf-benchmark plots --all`。输出位于 `reports/figs/paper/`。图 1（研究框架）和图 4（模型架构）需手绘；其余图和表由 [`src/wpf_benchmark/figures/`](../src/wpf_benchmark/figures/) 的独立函数生成。画面文字为英文，PDF 中的文字保留为可编辑字体，PNG 为 300 dpi。

### 日常用法

```powershell
wpf-benchmark run --model persistence --config configs/persistence.json
wpf-benchmark plots --all
wpf-benchmark plots --figures 6,7,13 --tables 1,2
wpf-benchmark plots --all --out reports/figs/paper --wind-direction 270
```

最后一个命令用传入的气象风向（度）覆盖图 2 根据清洗数据计算的主导风向。其他命令中的输入位置和输出位置相对于项目根目录。某图缺少素材时会打印 `SKIP figXX: 原因`，已经具备素材的图继续生成；绘图代码错误仍会报错，便于发现问题。

### 结果是怎样找到的

[`runner.py`](../src/wpf_benchmark/runner.py) 一次运行会保存 `main` 和 `all` JSON，另存一份 `<run_id>_arrays.npz`，并向 `reports/eval/index.jsonl` 追加两行索引。索引包含模型名、表名、种子、配置摘要、JSON 路径、创建时间、实验类型及清洗数据/结果代码摘要。图件只聚合当前数据与代码版本的结果；同模型同配置的多个种子可计算均值和标准差。没有索引的旧结果仍可通过文件名扫描读取，但不会与带版本摘要的新结果混合。

NPZ 字段和形状见第 5 节，`wind_speed/curtail_mask/last_power` 等额外字段用于案例图。读取时会与 JSON 的 `config.horizon` 和 `grid` 核对形状；不一致会报错。

`run` 默认保存数组；对普通模型可用 `--no-save-arrays` 关闭。持续性基线始终保存。`standard` 运行自动进入图 6、7、13 和表 1；W3 的 `ablation` 运行中，最终 `ours` 与 `barest` 也进入这些主结果图表，其余消融变体只进入图 9。新模型的固定颜色和英文显示名可在 [`style.py`](../src/wpf_benchmark/figures/style.py) 的 `MODEL_STYLE` 登记。

只想运行评估、不刷新图件时可给 `run` 加 `--no-plots`。图件会在下一次 `plots` 命令运行时更新。
