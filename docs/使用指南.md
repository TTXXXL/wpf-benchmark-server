# 使用指南：从数据到首个基线

本文集中说明首次运行、数据清洗原理和工程接入。当前批量实验直接按 [40 次统一重跑](实验训练.md)执行；全部文档见 [索引](README.md)。

## 环境与数据

项目支持 Python 3.8–3.12，基础依赖包含 NumPy、pandas、matplotlib 和 pyarrow；读取清洗数据需要 Parquet 支持，没有 CSV 降级读入路径。在项目根目录执行：

```bash
python -m pip install -e .
```

深度模型需要 PyTorch，可用 `python -m pip install -e '.[deep]'`；已有兼容 PyTorch 的环境可复用。GBDT 需要 `.[gbdt]` 或 `.[gbdt-fallback]`。服务器部署步骤见 [部署与同步](服务器部署与同步.md)。

原始文件放在 `data/raw/sdwpf/`：

- `sdwpf_245days_v1.csv`：134 台机组、245 天、每 10 分钟的运行数据。
- `sdwpf_baidukddcup2022_turb_location.csv`：机组位置。

预测目标 `Patv` 是有功功率，单位 kW；`Prtv` 是无功功率，不能作为限电指令。额定功率配置为 1550 kW。默认按 Day 划分：1–196 训练、197–221 验证、222–245 测试；历史窗口 144 步、未来 12 步。

## 首次运行

```bash
wpf-benchmark preprocess
wpf-benchmark fit-power-curve
wpf-benchmark eval selftest
wpf-benchmark run --model persistence --config configs/persistence.json --save-arrays --no-plots
```

`preprocess` 生成清洗 Parquet 和元数据；随后 `fit-power-curve` 将训练段四参数功率曲线写入元数据。已经具备这两份匹配文件及所需曲线时，可以从 selftest 开始。正在执行冻结批次时按批跑说明续跑。

| 产物 | 用途 |
|---|---|
| `data/processed/sdwpf_clean.parquet` | 模型和评估读取的物理单位特征与标记 |
| `data/processed/sdwpf_meta.json` | 训练段特征 min/max、功率曲线及相关统计 |
| `reports/cleaning_report.md`、`reports/figs/cleaning_*.png` | 缺失、补值、异常和清洗诊断 |
| `reports/eval/selftest_*.json`、`reports/eval_selftest.md` | M1/M2/宽松附表自检 |
| `reports/eval/<tag>_main_<timestamp>.json`、`<tag>_all_<timestamp>.json`、`<run_id>_arrays.npz` | 模型主表、附表和预测数组；run_id 为 tag 与同一时间戳 |

selftest 成功打印 `SELFTEST OK`。当前参考为 M1 3,188,016 个评分单元、持续性 MAE 约 99.83 kW；M2 3,636,220 个、约 104.95 kW。定义、允许误差与其他指标见 [评估与结果分析](评估与结果分析.md)。这些数字是指定数据快照及默认协议的回归参考。

持续性预测把刚看到的功率重复到未来 12 步，无需训练。后续模型使用同一评分群体比较。需要生成中文解读或做历史复核时，将结果文件带回本地开发版，按本地文档索引执行分析。

## 清洗原理与标记

清洗入口为 [preprocessing/sdwpf.py](../src/wpf_benchmark/preprocessing/sdwpf.py)。时间网格保留结构空行，不通过删除行改变发布时刻对齐。

- 当前连续缺失的前 3 步使用过去有效值；第 4 步起使用同时刻空间邻机值，距离倒数平方加权、k=12。此处的“3 步”是已发生缺失长度，不读取未来来判断缺口长度。
- 温度超出 −40–60℃ 置缺失后填补，风向回绕，负 `Patv` 截为 0。原始规则异常和截零观测功率另外保存，供 M1/M2 使用。
- 功率曲线参照和残差尺度仅从训练段拟合；离群功率打标后因果重补。清洗输出物理单位，归一化在训练/推理时用训练段统计完成。
- `m_missing/m_imputed/m_outlier` 表示原始缺失、发生补值和功率离群；`f_fault/f_curtail/f_stuck/f_farm` 表示规则筛选的疑似工况。它们不能代替有标签的故障或限电诊断。
- `m_missing_wspd/m_imputed_wspd` 与功率通道对应标记保留通道级信息；方法模型的风速监督另外排除 `f_stuck`。主表功率掩码按评估协议定义。

标记用于决定监督或评分资格，不等于删除整行。清洗后功率曲线更紧致是分布诊断，不能独立证明预测泛化改善。`preprocess` 会重写元数据，之后须重新运行 `fit-power-curve`；这会改变数据指纹，应在新批次准备阶段完成。

## 新增模型的契约

在 `models/` 新建文件，继承 [BaseForecaster](../src/wpf_benchmark/models/base.py)，使用 `@register_model("name")`，并在 `models/__init__.py` 导入。

1. `features` 按声明顺序组成 F 轴；`fit(train, valid)` 接收严格按天划分的数据。
2. `predict(history)` 输入为 `(N,F,input_window)`，批量接口 `predict_batch(histories)` 为 `(B,N,F,input_window)`。
3. 默认历史为物理单位；`history_scale="normalized"` 使用运行器提供的训练段 `self.scaler`。调整训练天数时缩放统计应重新从对应训练段计算。
4. 输出必须是 kW 的 `(N,H)` 或 `(B,N,H)`，运行器检查形状和有限性。需要日内相位时可设置 `needs_phases=True`。
5. 配置的 `protocol` 传给 ProtocolConfig，`model` 传给模型构造函数。新增模型配备配置与必要的契约测试，共用评估器。

首个测试预测读取测试前最后 `input_window-1` 步和当前测试时刻，目标为未来 t+h。具体时间轴约定见 [评估分析](评估与结果分析.md)。

开发验证在本地开发版使用已有运行时和测试进行，服务器只保留训练与标准评估入口。部署更新见[服务器部署与同步](服务器部署与同步.md)。
