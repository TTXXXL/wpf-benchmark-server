# 从数据清洗到首个基线

> **2026-09-30 口径更新**：新运行默认 M1，也可选 M2；本指南下文旧版 4,948,656 格、66.46 kW 等数字属于历史 M0，不能用于新自检。当前定义和基线见[目标掩码口径](目标掩码口径_M1_M2.md)。

这份指南按实际运行顺序介绍项目。先把原始数据清洗成 Parquet，再检查评估流程，最后运行第一个预测基线。下面的命令都在项目根目录执行。

## 开始前

使用 Python 3.8 环境，并确认已安装 `pyarrow`。在项目根目录安装本项目：

```powershell
python -m pip install -e .
```

把两个原始文件放到 `data/raw/sdwpf/`：

- `sdwpf_245days_v1.csv`：机组每 10 分钟的运行数据。
- `sdwpf_baidukddcup2022_turb_location.csv`：机组位置，清洗缺失值时会用到。

已经有 `data/processed/sdwpf_clean.parquet` 和 `sdwpf_meta.json` 时，可以从第 2 步开始。

## 1. 数据清洗

运行：

```powershell
wpf-benchmark preprocess
```

入口是 [`src/wpf_benchmark/cli.py`](../src/wpf_benchmark/cli.py)，实际清洗代码在 [`src/wpf_benchmark/preprocessing/sdwpf.py`](../src/wpf_benchmark/preprocessing/sdwpf.py)。它读取原始 CSV，整理时间和机组数据，补部分缺失值，并给异常、停机等数据加上标记。**打标记不等于把整行删掉**；评估时会根据标记决定哪些数据进入主表。

运行后主要看这几个文件：

| 文件 | 用途 |
| --- | --- |
| `data/processed/sdwpf_clean.parquet` | 后续评估和模型运行读取的清洗数据。 |
| `data/processed/sdwpf_meta.json` | 保存训练时段算出的特征范围，供模型使用。 |
| `reports/cleaning_report.md` | 查看缺失、异常和标记的数量。 |
| `reports/figs/cleaning_*.png` | 查看清洗结果的图。 |

## 2. 评估协议

评估协议就是所有模型共用的“考试规则”：用哪段数据测试、预测多远、哪些数据计分，以及怎样算误差。先运行自检：

```powershell
wpf-benchmark eval selftest
```

这一步涉及的 Python 文件：

| 文件 | 做什么 |
| --- | --- |
| [`src/wpf_benchmark/evaluation/config.py`](../src/wpf_benchmark/evaluation/config.py) | 保存默认规则：前 196 天训练、接着 25 天验证、剩余 24 天测试；看过去 144 个时间点，预测未来 12 个时间点。每个时间点间隔 10 分钟。 |
| [`src/wpf_benchmark/evaluation/selftest.py`](../src/wpf_benchmark/evaluation/selftest.py) | 用简单的持续性预测检查整套评估流程和参考结果。 |
| [`src/wpf_benchmark/evaluation/evaluator.py`](../src/wpf_benchmark/evaluation/evaluator.py) | 对齐预测和真实值，选出计分数据，组织各项结果。 |
| [`src/wpf_benchmark/evaluation/metrics.py`](../src/wpf_benchmark/evaluation/metrics.py) | 计算误差等具体数值。 |
| [`src/wpf_benchmark/evaluation/report.py`](../src/wpf_benchmark/evaluation/report.py) | 保存 JSON 结果和可读报告。 |

自检会生成 `reports/eval/selftest_main_*.json`、`reports/eval/selftest_all_*.json` 和 `reports/eval_selftest.md`。`main` 是主表，会排除协议指定的缺失、补值和异常标记；`all` 是附表，只要求真实功率有数值，所以可能包含补值行。平时比较模型，先看主表中的 `A_turbine.MAE_kW`：它表示预测功率平均差了多少千瓦，**越小越好**。

自检通过时会打印 `SELFTEST OK`。对这份 245 天的 SDWPF 数据，主表有效评分格数应为 4,948,656，持续性预测的主表 MAE 约为 66.46 kW。自检是检查规则和数据是否按预期工作，不是另一个需要训练的模型。更完整的规则见[评估协议原文](spec_eval_protocol.md)。

## 3. 运行首个基线

首个基线叫 `persistence`（持续性预测）：**把刚看到的功率值，当作未来 12 个时间点的预测值**。它不需要训练，但能给后续新模型提供一个比较起点。

```powershell
wpf-benchmark run --model persistence --config configs/persistence.json
```

[`configs/persistence.json`](../configs/persistence.json) 写着这次运行的时间窗口和数据划分。下面这些 Python 文件完成运行：

| 文件 | 做什么 |
| --- | --- |
| [`src/wpf_benchmark/models/persistence.py`](../src/wpf_benchmark/models/persistence.py) | 定义持续性预测。 |
| [`src/wpf_benchmark/runner.py`](../src/wpf_benchmark/runner.py) | 读取数据、准备历史窗口、调用模型预测，再交给同一个评估器打分。 |
| [`src/wpf_benchmark/data/windows.py`](../src/wpf_benchmark/data/windows.py) | 把连续数据整理成模型需要的历史窗口。 |
| [`src/wpf_benchmark/data/io.py`](../src/wpf_benchmark/data/io.py) | 读取清洗后的 Parquet 数据和元数据。 |

结果保存在 `reports/eval/persistence_main_*.json` 和 `reports/eval/persistence_all_*.json`。命令行也会打印两个表的 MAE。首个基线的主表 MAE 应与第 2 步自检接近；后续加入新模型时，使用同一套评估规则对比它们的主表结果即可。

如果 JSON 不好读，运行 `python scripts/analyze_persistence.py`。它会选取 `reports/eval/` 中最新的一对结果，生成中文解读 `reports/eval/persistence_analysis.md`。脚本在 [`scripts/analyze_persistence.py`](../scripts/analyze_persistence.py)；结果文件在别处时，可以同时传入 `--main 文件路径 --all 文件路径`。

如果要找模型接入位置，从 [`src/wpf_benchmark/models/base.py`](../src/wpf_benchmark/models/base.py) 和 [`src/wpf_benchmark/models/registry.py`](../src/wpf_benchmark/models/registry.py) 开始看；更详细的扩展方法见[架构说明](architecture.md)。

## 4. 生成论文图件

`run` 完成后会自动刷新论文图件；需要单独重画时执行：

```powershell
wpf-benchmark plots --all
```

图保存到 `reports/figs/paper/`，每张图都有 PDF 和 300 dpi PNG；表格有 `.tex` 和 `.md`。如需只生成几项，可以运行 `wpf-benchmark plots --figures 6,7,13 --tables 1,2`。命令入口在 [`src/wpf_benchmark/cli.py`](../src/wpf_benchmark/cli.py)，各图和表的代码在 [`src/wpf_benchmark/figures/`](../src/wpf_benchmark/figures/)；缺少输入的项目会显示 `SKIP` 和原因，其余继续生成。
