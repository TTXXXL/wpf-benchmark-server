# 实验批跑：本轮 40 次与旧 M1 套件

本文主体是用户已选择的本轮八组对照，各 seed 0–4，合计 40 次训练。本轮沿用现有模型，实现版本、数据、配置和环境统一冻结；不包含尚未实现的 D 因子拆分。没有连接实验服务器，也没有在本机启动这批研究训练。

旧 M1 41 次套件保留在文末附录，含不同模型且首次运行会重建数据，不作为本轮入口。旧图模型八组参数见 [模型与消融](模型与消融.md)。

## 八组矩阵

| 标签 | 骨干 | 损失 | current_power_skip | 低功率头 / 辅助权重 | 配置 |
|---|---|---|---|---|---|
| agcrn_noskip | AGCRN | MAE | false | 无 | graph_ablation/agcrn_mae_no_skip.json |
| agcrn_skip | AGCRN | MAE | true | 无 | agcrn_mae.json |

配置均位于 `configs/`。Protocol 固定 M1 target/eval、144 步历史、12 步预测、196 天训练及 25 天验证。测试为其后时段，早停仍只用验证损失；不因当前测试结果改阈值、训练损失或选种子。三个锚点对只差一个布尔量，Lite 损失对只差 loss，B/C 只差辅助权重，运行前自动断言。

## 运行入口

在 Linux 项目根目录，使用已安装项目依赖的 Python 3.8–3.12。入口不会安装软件，也不自动连接服务器。默认顺序执行 40 次，使用与已有批跑脚本相同的项目锁。

已有清洗数据时，默认复用并冻结，先检查命令：

```bash
python scripts/rerun_low_power_review.py --experiment lp_review_20261008_v1 --dry-run
python scripts/rerun_low_power_review.py --experiment lp_review_20261008_v1
```

新上传副本没有清洗数据时，显式准备一次：

```bash
python scripts/rerun_low_power_review.py --experiment lp_review_20261008_v1 --prepare --dry-run
python scripts/rerun_low_power_review.py --experiment lp_review_20261008_v1 --prepare
```

`--dry-run` 只打印命令，不写目录、不预处理、不训练。`--prepare` 仅允许没有两份清洗数据的全新副本；检测到任何现有文件即拒绝覆盖。准备顺序为 preprocess、fit-power-curve、eval selftest，随后冻结两份清洗文件。默认复用模式只跑 selftest，不重新清洗。不要在数据准备中断后用 --prepare 覆盖半成品；改用另一份干净项目或先核查半成品。

新实验使用未用过的 experiment 名；中断后**相同命令和参数**可续跑。成功结果按完整文件 SHA256、运行身份、M1 完整 protocol、配置、代码/数据指纹及数组对齐核验后跳过。完整预测写出后若中断于完成标记写入之前，可以验证后接续；缺失/损坏/重复结果会停下，不静默选最新或混合版本。

运行前和每个任务边界核验代码、八份配置、原始 CSV、清洗数据指纹。记录 Python/库版本和可得的 Git commit。变更代码/环境/数据/计划时拒绝续跑旧实验；Git 仓库的提交改变也会拒绝，因此文档更新的 git pull 同样应在批次启动前或结束后进行。冻结指纹来自运行环境自身；Windows 与 Linux 换行或 Parquet 物理字节可能不同，不要求它等于旧实验的指纹，只要求本批全部一致。完整原实验快照不再是这轮训练的前提；这轮是一个新的统一快照。

本计划用固定模型 tag，以便锚点分析器发现两格；实验之间靠 metadata 的 experiment 区分。每格 seed 0–4 必须唯一，不从目录中随意取共同子集。

## 运行后复核

执行目录为 `reports/rerun_m1/lp_review_20261008_v1/`，包含 manifest、40 个完成标记及控制台日志、results.csv、三个分析清单：

- `all_runs.json`：全部 40 次。
- `abc_history_runs.json`：A/B/C 各五种子。
- `p0_s0_runs.json`：P0 所需七组 seed 0；新的 Lite 无锚点 MAE 另见完整清单与锚点分析。

预测/主表/训练日志按项目原路径写入新时间戳文件。旧结果保留，不把新旧相加成十种子。

```bash
python scripts/review_diagnostics/analyze_anchor_ablation.py --reports reports/eval --experiment lp_review_20261008_v1 --out reports/review_lp_v1_anchor
python scripts/review_diagnostics/diagnose_low_wind.py --reports reports/eval --runs reports/rerun_m1/lp_review_20261008_v1/p0_s0_runs.json --out reports/review_lp_v1_p0
python scripts/review_diagnostics/rescore_m2.py --reports reports/eval --runs reports/rerun_m1/lp_review_20261008_v1/all_runs.json --out reports/review_lp_v1_m2
python scripts/review_diagnostics/analyze_history_groups.py --reports reports/eval --runs reports/rerun_m1/lp_review_20261008_v1/abc_history_runs.json --history-source local --project-root . --paired-seeds --history-steps 6 --threshold 1 --sensitivity --out reports/review_lp_v1_history
```

分析输出必须使用新目录，已有目录不覆盖。新的本地模式使用该批严格匹配的清洗数据，可补齐以前 NPZ 缺失的开头历史；无需 mismatch 选项。M2 是同一冻结预测的口径复核，不额外训练 40 次。不要在批跑途中重新 preprocess/fit-power-curve，后者会改变 metadata 和 data_digest。

主要报告整体 MAE、历史主群体 C−A 与 C−persistence、风速恢复/过渡诊断及代价；固定 K=6/v=1 主定义、同时保留九格敏感性。持续静风 S1 的现有收益不稳健，不把未来零值切片作为唯一成功终点。种子 SD 与时间块不确定性分开，40 次统一版本复现仍不能单独识别锚点内部机制。

本机入口验证包含 40 任务完整性、dry-run 无写入、准备防覆盖、中断续跑、同大小文件损坏检测和错指纹拒绝；未启动真实训练。原始 CSV 随上传 ZIP 提供，Git 不包含数据；使用纯 Git 新 checkout 时需先提供两份原始 CSV。


## 附录：旧 M1 41 次基线套件

以下内容描述仍可使用的旧套件，仅用于另行重建通用 M1 基线；不能和本文主体的 40 次计划混为同一批次。

在服务器项目目录激活已有 Python 3.8–3.12 环境后执行：

```bash
bash scripts/rerun_m1.sh
```

脚本使用当前环境的 `python`，也可以用 `PYTHON=/path/to/python bash scripts/rerun_m1.sh` 指定解释器。入口会定位项目目录并优先加载该目录的 `src/`。需要项目基础依赖、PyTorch，以及 LightGBM 或 XGBoost；缺少依赖会在预处理前退出，不会自动安装。

先查看命令计划（不写文件、不训练）：

```bash
bash scripts/rerun_m1.sh --dry-run
```

### 范围与口径

训练目标、验证目标和主表评分全部固定为 M1。每个模型保留当前配置中的损失函数、超参数与默认时间切分；这次是重建 M1 实验基线，使用关闭当前功率残差直通的原始配置，不加入状态特征或曲线修正。直通与 MAE/MSE 的旧图模型矩阵另见 [模型与消融](模型与消融.md)；本轮低功率八组使用本文前述新入口。

| 模型 | 默认种子 | 次数 |
|---|---|---:|
| persistence、seasonal_persistence、climatology、trend_persistence、farm_mean_persistence、linear | 0 | 6 |
| gbdt、lstm_seq2seq、patchtst、agcrn_lite、agcrn | 0–4 | 25 |
| barest、ours（configs/ours_consist_only.json） | 0–4 | 10 |

共 13 个模型、41 次训练/评估，顺序执行。旧 Wave 1 标为 `agcrn` 的简化骨干现在用 `agcrn_lite` 运行，论文架构的 `agcrn` 单独运行。`agcrn_lite` 只有功率 MSE；`barest` 仍有风速辅助头及损失；`ours` 在相同双头骨干上增加 λ_consist=0.1、λ_wake=0。原始 `agcrn` 默认 MAE，故该套件是现有完整配置比较，不是仅改变网络结构的消融。

这个旧套件沿用已经使用的 λ_consist=0.1，没有根据测试结果选 λ。现有 W0 为弱证据，不运行含尾流约束的配置，也不自动重做 λ 搜索。EDA、k 标定、历史 M0 掩码消融及旧 D1 诊断不属于这次 M1 训练重跑。若后续需要选参，应另开只读训练/验证段的实验。

### 准备、结果与续跑

首次执行依次运行 `preprocess`、`fit-power-curve`、`eval selftest`，重建含官方规则列的清洗数据和曲线，并核验 M1/M2 评价实现。预处理会刷新现有 Parquet 和元数据，不删除历史报告。自检通过后才开始模型训练。中断在准备阶段时，下次会重新执行准备阶段。

所有运行都保存预测数组，禁止自动调用可能混入旧报告的全局作图。结果位置：

- `reports/eval/`：带 `m1_rerun_<model>_s<seed>` 前缀的 main/all JSON、NPZ，以及追加的索引条目。
- `reports/train/`：对应训练日志。
- `reports/rerun_m1/m1_rerun/`：准备日志、每次运行的控制台日志、源文件及数据指纹、实际命令、完成标记和 `results.csv`。

`results.csv` 仅汇总该套件 M1 main 结果；`all` 是原有宽松附表，不是 M1。JSON 的 `mask_sensitivity` 仍提供同一预测下的 M1/M2 诊断，无须为此重复训练。

中途失败会立即停止，原样重跑 `bash scripts/rerun_m1.sh` 即可续跑。脚本检查已完成任务的主表身份及主表/附表/数组/训练日志的存在与大小，跳过完整运行；未完成的一次训练从头开始，不恢复 epoch 检查点。代码、配置、原始数据、环境或种子计划发生变化时，拒绝混入同一批次；已准备数据内容变更也会拒绝续跑。不要在套件运行期间修改代码、配置或数据，或另行启动其他训练/预处理进程。

启动独立的新批次，或先用单种子完成 13 次试跑：

```bash
bash scripts/rerun_m1.sh --experiment m1_rerun_v2
bash scripts/rerun_m1.sh --experiment m1_smoke --repeat 1
```

断开 SSH 后继续运行（在项目目录执行）：

```bash
mkdir -p reports
nohup bash scripts/rerun_m1.sh > reports/m1_rerun_console.log 2>&1 &
tail -f reports/m1_rerun_console.log
```

脚本不会删除旧 M0 结果，也不会将旧分数标为 M1。归档分析时保留本轮 manifest、CSV、对应 JSON/NPZ 和训练日志。服务器代码由开发版同步产生；脚本实现文件为 `scripts/rerun_m1.py`，与 `.sh` 一起部署。
