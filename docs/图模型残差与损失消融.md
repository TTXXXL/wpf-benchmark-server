# AGCRN / Lite：当前功率残差与 MAE / MSE 消融

2026-09-30 新增。训练目标、验证目标与主表评分默认固定 M1；JSON 的 `mask_sensitivity` 同时给出同一预测下的 M2 诊断。模型名为 `agcrn` 和 `agcrn_lite`。

## 网络如何直接使用当前功率

开启 `model.current_power_skip=true` 时，两种网络都采用：

```text
预测功率(t+h) = 当前功率(t) + 网络预测残差(h)
```

- `agcrn` 保留完整时序、自适应图、节点自适应参数和直接多时距输出头；将该头解释为各时距的有符号残差，再加同一个当前功率。
- `agcrn_lite` 保留历史池化和图循环结构；在池化前取当前功率作为解码器初始输入。每一步输出相对同一个 P(t) 的残差，并将重构后的预测功率反馈给下一步，不能反馈残差本身，也不能把每步残差累加成累计变化。
- 残差允许正负。功率输出层的权重和偏置初始化为零，因此训练前的预测等于持续性；第一步先更新输出头，后续编码器也获得梯度。
- 训练及验证均对重构后的功率计算选定的 MAE 或 MSE，按同一个目标损失早停。推理时继续使用已有的 [0, 1550] kW 裁剪。
- 当前功率与残差在同一归一化尺度相加，然后仅做一次功率反归一化；不能把已经训练好的绝对功率输出直接加 P(t)。

P(t) 指输入历史的最新有限、因果清洗后的 Patv，并非未经清洗的原始传感器值，也不额外要求它满足 M1 的目标 flag。若最新格仍缺失或无穷，在同一历史窗口内向过去寻找最后一个有限 Patv；整个窗口都没有有限功率时回退到 0 kW。回退值经过训练段 scaler 转换，保证 scaler 的最小值非零时也代表 0 kW。训练和推理在选择锚点前保留缺失位，随后将网络其他非有限输入置零，不读取未来数据。

`current_power_skip=false` 保留原绝对功率输出方式和原初始化；Lite 的解码初始输入仍为最后一段池化均值。这个开关对应“最新功率解码起点 + 残差直通 + 零输出头初始化”这一整套改动，当前八组实验未单独拆分这三个因素。

`barest` / `ours` 虽然调用同一个 Lite 网络类，但目前仍使用其默认关闭直通的双头版本。该轮消融只覆盖用户要求的两个纯功率图模型。后续比较物理约束时需要在相同直通设置下另行配置方法模型。

## 四组新配置与四组对照

| 网络 | 损失 | 直通开启配置 | 对应关闭配置 |
|---|---|---|---|
| AGCRN | MAE | `configs/agcrn_mae.json` | `configs/graph_ablation/agcrn_mae_no_skip.json` |
| AGCRN | MSE | `configs/agcrn_mse.json` | `configs/graph_ablation/agcrn_mse_no_skip.json` |
| Lite | MAE | `configs/agcrn_lite_mae.json` | `configs/graph_ablation/agcrn_lite_mae_no_skip.json` |
| Lite | MSE | `configs/agcrn_lite_mse.json` | `configs/graph_ablation/agcrn_lite_mse_no_skip.json` |

除结构必需参数不同，两网络统一 hidden=64、layers=2、emb=10、lr=0.001、batch=16、epochs=30、patience=5、训练 stride=6、weight_decay=0、dropout 配置值=0。当前两个骨干实际均不调用 Dropout。每个骨干的 MAE/MSE 和开关对照仅修改这两个因素。

原 `configs/agcrn.json` / `configs/agcrn_lite.json` 显式记录关闭直通，分别保留原 MAE/MSE，供原 41 次 M1 套件使用。要运行修复后的网络，请使用上表的新配置。日志与结果 JSON 的 `model_config` 都记录实际 `loss` 和 `current_power_skip`，不能把直通开启结果标成原始论文 AGCRN。

## 批量运行

进入服务器项目目录并激活原 Python 3.8–3.12 环境：

```bash
git pull --ff-only
bash scripts/rerun_graph_ablation.sh --dry-run
bash scripts/rerun_graph_ablation.sh
```

默认运行四组直通开启配置，各用 seed 0–4，共 **20 次**。只运行 MAE 或 MSE 配对组：

```bash
bash scripts/rerun_graph_ablation.sh --loss mae --experiment graph_skip_mae
bash scripts/rerun_graph_ablation.sh --loss mse --experiment graph_skip_mse
```

每条是两网络 × 五种子，共 10 次。完整“架构 × 损失 × 直通开关”消融：

```bash
bash scripts/rerun_graph_ablation.sh --include-no-skip --experiment m1_graph_factorial
```

八组各五种子，共 **40 次**。先做八组单种子试跑可用：

```bash
bash scripts/rerun_graph_ablation.sh --include-no-skip --repeat 1 --experiment m1_graph_factorial_smoke
```

脚本复用 M1 套件的预处理、曲线拟合、自检、预测数组保存及续跑机制，只需基础依赖和 PyTorch，无需 GBDT 后端；不会自动安装依赖。它与 `rerun_m1.sh` 共用项目锁，避免同时刷新数据。不要在训练期间另开预处理、训练或修改源码。

第一次运行会重新生成清洗数据、曲线和自检报告，然后顺序训练。中断后运行相同命令可跳过完整任务。改变代码、配置、数据、环境、种子范围或实验组合时须使用新 `--experiment` 名称，不会混入旧批次。旧 `m1_graph` 的实验结果保留，也不能代替新八组的对照重跑。

汇总保存到：

```text
reports/rerun_m1/<experiment>/results.csv
```

CSV 包含 `job`、模型、种子、`loss`、`current_power_skip`、配置路径、M1 MAE/RMSE、运行 ID 和 JSON 路径。主表/附表/NPZ 在 `reports/eval/`，训练日志在 `reports/train/`，批次指纹、完成标记和控制台日志在上述批次目录。

## 单独运行一组

例如 AGCRN 残差直通 + MSE，5 种子：

```bash
python -m wpf_benchmark run --model agcrn --config configs/agcrn_mse.json \
  --target-mask m1 --eval-mask m1 --seed 0 --repeat 5 \
  --experiment graph_skip_mse_single --tag agcrn_mse_skip --save-arrays --no-plots
```

Lite 对应替换成 `--model agcrn_lite --config configs/agcrn_lite_mse.json`。单独命令没有批次续跑标记；长批次优先使用上面的 Bash 入口。

## 如何读消融结果

1. 固定架构、损失与种子，比较开关，得到当前功率方案的增益。
2. 固定架构、开关与种子，比较 MAE/MSE，得到训练目标与对应早停规则的影响。
3. 固定损失、开关与种子，比较两网络，减少原先 MAE/MSE 混杂。

按“网络、loss、current_power_skip”分成八组，各组独立报告五种子的均值和标准差；同时检查总体、h=1/6/12、低风速偏差、日电量及同预测的 M2 敏感性。批次中同一注册名会出现多个配置，当前全局作图及旧按模型汇总的脚本可能将其混合；本套件不自动调用它们，应使用 CSV 的完整分组或明确选择各组 run_id。

已有测试集参与了问题诊断。新增方案的选参仍应只使用训练/验证段，并补充其他时间留出段或滚动验证。实现已通过本地合成数据训练、预测与梯度检查；实际 SDWPF 收益必须重新训练后判断。
