## 当前实验：固定 M1 早停的 M2 加权训练

```bash
git pull --ff-only
python -u scripts/run_study.py --study m2_weighted
```

共九次训练：现有 C 模型使用 M2 训练，M1 共用目标权重为 1，M2 额外目标权重分别为 1、0.5、0.25，各跑 seed 0、1、2。全部使用未加权的 M1 功率 MAE 选择最佳权重。架构、MAE、状态损失系数 0.05 及其他参数一致。训练 Day1–196，验证 Day197–221；只运行验证。

上一轮六次训练已经完成。密集统一复评分中，M2 训练使 M2 MAE 从 131.96 降至 130.32 kW、额外样本从 178.69 降至 158.19 kW，但 M1 从 123.08 升至 125.02 kW，恢复段也退步，未通过预设门槛。这些是三种子验证均值，不是测试结论。保留已有报告和权重，不重跑上一轮。

本轮权重 1 与上一轮 M2 模型比较，检验改变早停口径的效果；权重 0.5、0.25 与本轮权重 1 比较，检验降低额外目标监督强度的效果。统一与已核验的上一轮 C_M1 三种子对照。功率损失与状态 BCE 使用相同目标权重，按权重总和归一；状态损失系数仍为 0.05。权重只用于训练损失，不改变输入和评分规则。M2 提升不能单独证明输入噪声鲁棒性。

候选选择只使用密集验证结果：M1 总体均值不退步且至少两颗种子不退步；M2 总体改善至少 0.5%、额外样本改善至少 3%，各至少两颗种子改善。M1/M2 的恢复段及 h1 平均退步不超过 1%、最差种子不超过 3%；M1 持续低功率与 S1 静风均值不退步。全部过关后选 M2 均值最低者，依次用 M1 均值、较小额外权重打破平局。同步报告唯一目标和事件等权敏感性；没有候选过关就保留 C_M1，不自动追加种子或测试。

## 后续实验与历史入口

`configs/studies/m2_robustness.json` 保留上一轮六次训练的冻结身份。其源码摘要属于旧版本，更新后不要重新运行或收集旧计划；已有交付包与核验后的结果足够用于比较。

新的验证实验优先复用 `scripts/run_study.py`，在 `configs/studies/` 放一份计划，引用已有模型配置。明确模型、种子、变体和冻结指纹后，通过同一个入口训练和交付。一次性分析及历史证据留在项目外；只有用户明确要求清理时才整理已替代的配置与说明，不安排定时任务。

以下旧训练入口保留，因为已有消融和批跑仍依赖它们。只在明确要求复现时使用；更新代码无需重跑历史实验。

| 入口 | 用途 |
|---|---|
| `scripts/rerun_low_power_review.py` | 八组五种子的低功率历史实验，默认复用处理数据 |
| `scripts/rerun_graph_ablation.py` | 图骨干、损失与当前功率开关消融 |
| `scripts/rerun_m1.py` | 旧 M1 基线套件，也是批跑公共执行模块 |

这些入口有各自的准备与续跑规则，先使用 `--help` 和 `--dry-run`。旧 M1 套件会进行数据准备，不应在当前冻结数据上启动。历史详细操作说明及阶段 2/3 工具已归档到本地项目外的 `experiment-analysis/maintenance_archive/`，不随服务器仓库分发。
